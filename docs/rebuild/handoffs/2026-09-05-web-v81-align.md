## 本轮设计范围

1. 学生通知：保留成员关系、打卡审核/补证、免测、认证、原始耐力跑、反馈、维护/恢复；整条省略明确成绩/换算分/等级/排名。补证/运动通知进入打卡记录，不误开免测页。
2. 维护页：展示管理员中英文公告和预计恢复时间；有服务器确认的补证剩余时间时显示「计时已暂停」和剩余时间，否则「状态暂不可确认」。预计恢复时间不是补证截止。
3. 六类固定中英公开原因 + 系统「补证逾期」；教师退回/判无效按动作过滤选项，必须选分类，可选一句原文公开补充说明；无「其他」兜底。学生只认精确分类名，不猜测自由文本。
4. 审核展示用业务环节词：待 AI 检查、待教师复核、待补证、补证待复核、技术处理中、有效（并区分已计入/未计入）、无效。Contract 只有 `VALID`/`INVALID` 时，未知中间态标「审核阶段暂不可用」，不猜测。
5. 主题色恢复原 Web 值（主色 `#007AFF` / 辅色 `#FF9500` / 成功 `#248A3D` / 错误 `#FF3B30`），不再改成 Android 对比度色板。

## 业务有、合同 1.2.0 没有（或不够）

下列能力业务正文已写明。本轮只做客户端展示/采集设计，**不把它们写成已接受的 OpenAPI 字段**。生产写入必须等独立 Contract CR 升版后再接。

| 业务能力 | 业务出处 | Contract 1.2.0 实际有什么 | Web 本轮怎么处理 |
|---|---|---|---|
| 教师三个动作：通过、退回补证、判为无效；退回进入待补证，不是立即 `INVALID` | 总览 §12.1；教师 §9.2 | `appendExerciseRecordReview` 的 `result` 只有 `VALID` / `INVALID`；描述要求必须改变当前结果 | 退回对话框已按业务采集分类、24/72 小时窗口和公开说明。现有 helper 仍 POST 非合同字段 `RETURN_FOR_PROOF` + `proofWindowHours`，**不能当作正式协议**。缺独立「退回补证」operation |
| 六类固定公开原因、按动作限制选项、禁止「其他」 | 总览 §12.2；`BD-20260904-01` | `studentVisibleReason` 是自由字符串，无枚举、无动作适用范围 | 客户端用业务中英标签做选择器；写入时把精确中文分类名（及换行后的原文补充说明）放进现有自由文本。无合同 `reasonCode` 枚举 |
| 公开补充说明与固定分类分离；不设隐藏审核备注 | 总览 §12.2 | 只有一个 `studentVisibleReason`，没有独立 `publicSupplementalNote` | UI 分两栏采集；拼接进同一自由文本。读回只在首行精确等于分类名时拆出补充说明 |
| 系统公开原因「补证逾期 / Supplementary evidence deadline missed」；来源是系统，不进教师下拉 | 总览 §12.3 | `RecordReview.actorType` 有 `SYSTEM`/`TEACHER`，但 `result` 仍只有 `VALID`/`INVALID`，没有系统原因枚举 | 学生展示：`actorType=SYSTEM` 且文案精确匹配，或旧 wire `PROOF_OVERDUE_INVALID` 时显示系统原因。合同未区分「教师判无效」与「系统逾期」的原因码 |
| 中间审核环节：待系统/AI、待教师、待补证、补证待复核、技术处理中 | 总览 §12.1；学生 §7.7 | 列表筛选和 `currentReview.result` 只有 `VALID`/`INVALID` | 展示词表按业务；能映射才显示环节，否则「审核阶段暂不可用」。不把中间态写成合同 enum |
| 有效 ≠ 已计入；分别展示可计分钟、实际计入分钟、未计入原因 | 总览 §11.3；学生 §8.1–8.2 | `creditedMinutes` 枚举仍是旧阶梯 `0 / 60 / 120`，与现行「达门槛后按整分钟、单次上限 60」不一致 | 有效记录按是否有计入分钟分「已计入 / 未计入」。分钟计算仍受旧合同阶梯约束，不能按 V8.1 真算 |
| 维护期间暂停学生补证计时和教师 SLA；展示剩余时间；预计恢复时间不是截止 | 总览 §12.3；学生 §3；管理员 §13 | `SystemMode` + `MaintenanceAnnouncement` 只有 `estimatedRecoveryAt`，没有补证剩余秒、暂停区间、恢复后新截止 | 有旧预览字段 `remainingSeconds` 才显示暂停+剩余，否则 Unavailable。客户端不本地判逾期、不把预计恢复当截止 |
| 正式补证：原记录追加第二版材料；受理结束学生计时；补证后教师只能通过或判无效 | 总览 §11.4、§12.3 | 合同补证 operation 只覆盖免测/认证 `applications/{id}/supplements`，没有运动记录补证包 | 学生补证入口保持已有 UI。**没有**合同运动补证提交/受理字段，不能宣称生产补证已接通 |
| 游泳 15 分钟锁定 + 已受理同批 30 分钟续传；未完成传输不进有效审核 | 总览 §11.5 | 有会话 `resume`，没有「锁定批次 / 同批续传窗口 / 延迟说明」运动材料协议 | 不私造续传接口。锁定批次续传仍缺合同 |
| 课程关闭禁止新起点，关闭前已确认链条继续 | 总览相关关闭条款；教师/管理员关闭节 | 课程状态存在，但没有「关闭后继续既有审核/补证/续传」的专用字段或例外 | 不在客户端截断已有记录展示；新提交是否被拒以服务器为准 |
| 站内通知：审核通知带同一公开分类和补充说明；不发分数/换算分/等级/排名；仅站内 | 学生 §10.1 | `Notification` 有 `title`/`body`/`notificationType`/`targetRoute`（含 `FINAL_GRADE`），没有公开原因结构化字段 | 客户端按业务省略成绩类文案；`FINAL_GRADE` 路由本身与「不向学生发成绩」冲突，需合同/产品后续处理。分类名仍从正文猜测，不是独立字段 |
| 教师 SLA：两个学校工作日、逐轮起止、维护暂停后续计 | 总览 §12.4 | 无教师 SLA 剩余时间、工作日日历或轮次标识 | 工作台不伪造 SLA 倒计时 |

既有 `CR-20260901-005`（discriminator 显式映射）仍是 `PROPOSED / BLOCKING`，与上表不是同一组缺口。上表需要**新的** Contract CR，不能并进 005，也不能把 Web 目录里叠入的 1.3.0 generated 绑定当成 `main` 已接受协议。
