# P2A Android 学生端用户流程

本文件把 v8.0 和 P2W 设计映射为 Android 导航与页面反馈。箭头表示 UI 流向，不代表已有接口或 Backend 已实现。

## 1. 启动与恢复

```text
启动 PAGE-STU-001
├─ 系统维护 → PAGE-STU-002 → 重新查询系统模式
├─ 未同意隐私 → PAGE-STU-003
│  ├─ 拒绝 → 留在受限入口或退出
│  └─ 同意 → PAGE-STU-004 → PAGE-STU-005
├─ 无登录会话 → PAGE-STU-004 / 005
├─ 需要强制绑定 → PAGE-STU-009
└─ 已登录 → 恢复原页面、未完成会话或 PAGE-STU-020
```

Android 平台要求：

- 系统 Splash 只承担启动，不在 Splash 中伪造登录或加载成功。
- 本地会话只能决定先显示什么；需要服务器事实的状态必须保留加载、失败和重新查询反馈。
- 维护恢复时间只作提示，倒计时归零不能自行切换到正常模式。
- 进程被杀后，未完成运动、媒体草稿和锁定上传分别恢复；不得把 UI 内存状态当成已提交。

## 2. 邮箱登录与身份恢复

```text
PAGE-STU-005 登录方式
├─ 学校邮箱 → PAGE-STU-006
│  ├─ 验证成功且已激活 → PAGE-STU-020
│  ├─ 需要绑定/激活 → PAGE-STU-009 → PAGE-STU-010 → PAGE-STU-020
│  └─ 身份无法匹配 → PAGE-STU-008
└─ 扫码邀请 → PAGE-STU-030 → PAGE-STU-031
   └─ 邮箱验证 PAGE-STU-006 → 入班确认 PAGE-STU-034 → 结果 PAGE-STU-035
```

- 学生不使用密码登录。
- 验证码发送、验证和身份匹配是不同状态，不合并成一个“登录失败”。
- 身份恢复页面不得承诺不存在的自动审批；无 Backend 阶段使用明确的待接入说明和可评审状态。
- 页面及日志不得显示完整验证码、Token、邮箱认证凭据或真实学生资料。

## 3. 已登录学生入班

```text
PAGE-STU-021 课程
├─ 扫码 PAGE-STU-032 ─┐
└─ 邀请码 PAGE-STU-033 ├→ PAGE-STU-034 确认 → PAGE-STU-035 结果
                       ┘
```

结果必须独立区分：

- 成功加入；
- 同一学期已经存在有效教学班；
- 邀请自然过期；
- 已登记流程的 10 分钟宽限已经耗尽；
- 邀请被撤销或课程已关闭；
- 无权限；
- 网络/服务失败，可安全重试；
- 结果未知，回到课程页重新查询，不显示假成功。

默认邀请时长 30 分钟，教师可设 5—120 分钟。自然到期宽限不可刷新；撤销和关闭没有宽限。

## 4. 首页、课程与进度

```text
PAGE-STU-020 首页
├─ 当前课程 → PAGE-STU-021
├─ 开始真实运动 → PAGE-STU-022
├─ 记录与进度 → PAGE-STU-023 → PAGE-STU-050 → PAGE-STU-051
├─ 原始耐力结果 → PAGE-STU-052
├─ 待补充任务 → PAGE-STU-060
└─ 站内通知 → PAGE-STU-025
```

共同信息口径：

- 总目标 1,200 分钟，同时显示两个类别的目标、已计入和剩余分钟。
- 记录详情区分实际时长、有效分钟、计入分钟。
- “有效但因日/周/类别/总目标约束未计入”不能显示为“无效”。
- 学生只看本人事实和原因，不看最终成绩、换算分、等级、排名、内部模型分数或教师内部备注。
- `PENDING` 在学生端显示“已退班”；仍可查看允许保留的本人历史，但不可开始新的课程运动。

## 5. 真实运动、证据和提交

```text
PAGE-STU-022 打卡准备
→ PAGE-STU-040 ACTIVE
↔ PAGE-STU-040 PAUSED
→ PAGE-STU-040 COMPLETED
→ PAGE-STU-041 证据采集
→ PAGE-STU-042 上传/受理/恢复
├─ 已受理 → PAGE-STU-050 / 051，状态为待检查或待审核
├─ 上传中断 → PAGE-STU-042 RESUME
├─ 游泳完全离线 → PAGE-STU-043 → 等待人工处理
└─ 未受理/未知 → 保留批次与重试入口，不显示有效或计入
```

UI 必须体现以下边界：

1. 会话状态是 `ACTIVE ↔ PAUSED → COMPLETED`，时间与业务日期以服务器事实为准。
2. 起算门槛默认 30 分钟，可配置 30/45/60；达到门槛后按实际整分钟，单次最多计入 60 分钟。
3. 每日最多一条、每周默认三条且可配二/三/四条，都是“计入限制”，不是“运动限制”。
4. 达到日/周上限、类别目标或总目标后，打卡入口仍允许开始真实运动，并预先说明可能不计入。
5. 提交/上传成功只表示材料被系统接受；不得立即显示 VALID、通过或计入分钟。
6. 运动证据按版本管理；补充版不能覆盖或改写原版。

### 游泳分支

```text
选择游泳
→ PAGE-STU-041 前照槽位 + 后照槽位（总计 2—6 图，可选 1 视频）
├─ 结束后 15 分钟内首次受理 → 锁定批次
│  └─ 同批次可在 30 分钟内续传
├─ 完全离线 → 24 小时内 PAGE-STU-043 提交延迟说明
└─ 已被退回补充 → 使用 PAGE-STU-060 的 24/72 小时窗口，不再套 15 分钟规则
```

不得在禁拍区域引导取证，也不得允许学生事后补造本应在运动前拍摄的前照。

## 6. 审核与一次补充

```text
原记录提交
→ 系统/AI/教师/技术处理状态
├─ 有效 → PAGE-STU-050 / 051 显示有效及是否计入
├─ 无效 → PAGE-STU-051 显示公开原因
├─ 技术处理中 → PAGE-STU-051 / 025 显示等待，不处罚学生
└─ 退回补充 → PAGE-STU-025 → PAGE-STU-060
   → 提交唯一一次补充 → PAGE-STU-061
   → 等待教师复核
   ├─ 有效
   ├─ 无效
   └─ 到期未交：系统追加逾期无效
```

- 教师退回时选择从退回时刻起算的 24 或 72 小时总窗口。
- 学生不得自行延期，也没有第二轮补充。
- 到期前已受理的补充继续等待教师复核，不因教师迟审而过期。
- 平台故障顺延是系统治理行为，UI 只展示服务器给出的新截止和原因。
- 固定退回原因分类尚未确认；设计稿使用中性文本，不创建客户端枚举。

## 7. 原始耐力、免测与认证

```text
PAGE-STU-023 / 024
├─ PAGE-STU-052 原始耐力结果
└─ PAGE-STU-070 免测/认证申请与历史
```

- 原始耐力结果只显示教师确认的项目、时间和日期，或免测事实。
- 未确认显示空态，不能显示 0 分、预测分或换算等级。
- 免测/认证同一申请最多 3 张 JPEG/PNG/WebP，每张 10 MB。
- 认证怎样分配计入由服务器业务事实决定；Android 不自行计算、不照搬 Web 旧“只能计入某一类别”的文案。

## 8. 账户与支持

```text
PAGE-STU-024 我的
├─ PAGE-STU-080 账户信息
├─ PAGE-STU-081 设置
├─ PAGE-STU-082 账户注销
├─ PAGE-STU-083 已验证邮箱
├─ PAGE-STU-084 帮助中心
├─ PAGE-STU-085 反馈
├─ PAGE-STU-086 关于
├─ PAGE-STU-087 更新日志
└─ PAGE-STU-088 隐私政策
```

业务通知仅通过站内通知展示；不设计设备 Push、短信或业务邮件开关。邮箱仍可用于身份验证，不等于业务邮件通知渠道。

## 9. 跨角色触发关系

| 教师/管理员动作 | 学生端必须出现的事实 | 不得出现 |
|---|---|---|
| 教师发布课程规则 | 课程页和打卡准备页显示只读规则快照 | 学生修改规则 |
| 教师退回记录 | 通知、详情和一次补充任务显示公开原因与截止 | 内部模型分、教师私密备注、第二次补充 |
| 学生按时补充 | 补充已接收并等待教师复核 | 立即显示有效/计入 |
| 教师确认原始耐力结果 | 只读时间、项目、日期 | 换算分、等级、排名 |
| 管理员进入维护模式 | 全屏维护页及可选预计恢复时间 | 本地倒计时自动恢复 |
| 教师/管理员处理反馈 | 站内通知和反馈状态 | 未确认的处理人或外部渠道承诺 |

## 10. 无 Backend 的交互边界

- Compose 评审态可以展示完整流程和状态，但所有样例必须标识为本地/演示数据。
- 正式路径不得用延时、Toast 或本地布尔值模拟服务器成功。
- 需要写操作的评审按钮应进入明确的 UI 演示结果或禁用态，并显示“尚未接入服务”；不能改变正式存储。
- 后续接口到位时，UI 映射服务器事实；客户端不得增加本文件之外的新业务状态。
