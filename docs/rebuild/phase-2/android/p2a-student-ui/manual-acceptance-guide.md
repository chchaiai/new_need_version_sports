## 2. 首轮准备：用户操作

1. 在 Android Studio 使用 Open 打开上表的 **BNBU-ANDROID** 目录，确认可见 `app`、`settings.gradle.kts` 和 `gradlew.bat`。不要打开 Week 9 工程或 Web 压缩包作为开发工程。
2. 如要求选择 Gradle JDK，使用已安装的 `C:\Program Files\Android\Android Studio\jbr`；SDK 已位于 `C:\Users\32631\AppData\Local\Android\Sdk`。让 Android Studio 完成工程识别；本步不接受自动升级 AGP、Gradle、Kotlin 或迁移工程的提示。出现错误时保留不含敏感信息的错误摘要。
3. 使用独立测试模拟器，建议命名 `BNBU_P2_UI_Review`。检查到现有 `v1` 为 Pixel 8、镜像目标 `android-37.0`，且本机目前只发现该系列已下载镜像。可在新模拟器中复用已下载镜像完成首轮 UI 冒烟，但必须记录实际系统版本，不能据此宣称覆盖全部受支持 Android 版本。后续兼容性覆盖由 Reviewer 确认。
4. 不卸载、不 Wipe Data、不清空现有 `v1`，也不直接覆盖其同包名应用。本地评审入口会清除该 App 的旧认证状态，因此首次使用独立环境。真机若已有同包名历史测试版，先回报现状。
5. R11 获用户开始后，由用户在专用环境安装上表 R10 构建并核对指纹的 `app-debug.apk`，再点击应用图标启动；若改用 Android Studio Run，Android Studio 可能重新构建，必须记录该新 APK 指纹，不能沿用上表 SHA。
6. 首轮仅使用虚构评审数据。关闭测试设备网络后进行本地页面检查，不输入真实邮箱、不发送验证码、不使用真实邀请、不提交或注销真实账户。项目不需要 Backend、数据库、COS 或新 GitHub 下载才能完成这部分检查。

本轮不自动启动、安装、控制模拟器或真机。连接设备后的自动化测试由 Codex 执行并单独记录；手动页面操作由用户完成。

AndroidTest APK 不是手工评审所需安装包。其 CoreJourneyUiTest 会在测试前后清空被测 App 状态；以后运行时必须另行确认使用可重置的专用测试安装，不能直接在留有手工评审草稿或历史账户数据的安装上执行。

## 3. 首次进入与最小冒烟

按实际出现的页面依次操作；曾经完成的引导可能不再出现，记为“本次未触发”，不要清空历史数据强制重现。

1. 冷启动：系统 Logo 后应立即交给明确的“正在检查服务状态”画面，不能在 Logo、白屏或黑屏上等待网络。当前无 Backend 时应进入“暂时无法连接服务”，点击“重试”后重新出现 Loading；记录两个状态和按钮截图。
2. Debug 本地评审：错误页应显示“进入本地 UI 评审”和合成数据说明；点击后直接进入明确标识的免登录评审。Staging/Release 不应有此入口，不能用 Debug 结果代替正式系统模式确认。
3. 首次隐私页：在专用测试环境查看正文和拒绝/同意入口，确认没有越过门控；需要继续测试时由用户选择同意。隐私正文存在已登记的 Push/法律待确认问题，此处只验收渲染和门控。
4. “加入课程”引导：查看各页，点击“直接登录”。首次路径缺失时记录，不假装已截图。
5. 登录页：如果不是从启动错误页直接进入本地评审，则查看底部“免登录测试入口”。如同意项未勾选，观察入口禁用；勾选后点击“以测试学生身份进入”。不使用邮箱验证码登录。
6. 如出现“运动指引”，查看并点击“进入首页”或“跳过”。
7. 首页应出现本地测试数据横幅、虚构学生信息和五个标签：**首页 / 课程 / 打卡 / 记录与进度 / 我的**。横幅缺失、进入真实账户、崩溃或明显越界时先停止该用例并记录。
8. 依次打开五个标签，各留一张完整截图；检查能滚动到最后一项、没有内容被底部栏遮住，标签切换和系统返回可用。

首轮回传：是否成功进入、五张主页面截图或失败页面截图、设备名称/系统版本、语言/主题。只截图虚构数据，不传完整 Logcat 或含凭证的设置。

## 5. 七状态的取证办法

每页至少登记正常态和关键异常态，每个页面组核对七状态。未触发状态保留 `NOT_RUN` 或带原因的 `BLOCKED`，不可全部填 PASS。

| 状态 | 当前可操作方式 | 无法据此证明的内容 |
|---|---|---|
| NORMAL | 本地学生主页面、记录和补充预览 | 真实服务数据正确性 |
| LOADING | 仅记录实际出现的启动/读取过程；没有出现就记待证据 | 源码含进度条不能代替运行截图 |
| EMPTY | 帮助搜索无匹配词；通知/记录的实际空态 | 某组空态不能代替其他所有组 |
| ERROR | 无服务时若自然出现错误，记录可理解性与重试/返回；不输入真实数据触发 | 网络错误不等于业务拒绝或记录无效 |
| FORBIDDEN | 扫码相机拒绝可测系统权限；补充写禁用可测无服务边界 | 相机权限拒绝不能代替已退班/跨角色业务无权限状态 |
| MAINTENANCE | 当前 local 环境没有手动维护开关，待专门评审状态或服务事实 | 不能通过断网充当维护，也不能用系统时钟切换 |
| RESUME | 普通页面旋转、后台返回、语言切换；观察本地模式是否重入 | 进程结束后本地身份为内存态，可能需重新点击评审入口；不能因此宣称上传批次或真实认证恢复已验证 |

缺少评审入口会阻塞对应页面/状态的设计取证，而不必等 Backend 才能讨论解决方案；后续可在单独 UI 批次补充明确标识的只读评审入口。本步只登记，不改生产路由或核心状态。

## 6. 布局与 Android 交互

1. 先中文浅色竖屏，再英文、深色；通过“我的→设置”改变语言与主题。每次切换后复查五个主标签、补充页、记录详情和设置。
2. 在测试设备系统设置中放大字体，记录实际比例；再看长标题、状态、底部按钮和英文换行，不能出现遮挡或无法滚动。没有完成某比例不填通过。
3. 横屏复查登录、运动选择、补充、反馈和设置。输入框弹出键盘时检查标签、错误文字和主按钮是否可访问。
4. TalkBack 下核对九种运动名称与选中态、底部标签、返回、通知图标、禁用按钮；检查焦点顺序和状态文字，避免装饰图标重复播报。
5. 扫码页首次拒绝相机、再次进入、系统返回。真机相机/麦克风和媒体边界仅在相应页面可达后取证，当前不可达则登记。
6. 只对合成表单测试旋转、后台返回和恢复；不要清理数据、卸载、调整系统日期或终止历史测试会话。首次冷启动应在独立模拟器完成。
