# P2A Android 学生端状态矩阵

## 1. 统一状态词汇

| 状态 | Android UI 含义 | 允许操作 | 禁止表现 |
|---|---|---|---|
| `NORMAL` | 当前页面事实已可显示或表单可正常输入 | 页面主操作、次操作、导航 | 用本地样例冒充服务器真实结果 |
| `LOADING` | 正在读取或提交，结果未知 | 取消（仅安全时）、返回（不破坏请求时）、无障碍状态播报 | 闪现旧成功数据、无限无说明转圈 |
| `EMPTY` | 请求成功但没有对应数据，或该学生尚未产生该事实 | 给出原因、下一安全动作或只读说明 | 显示 0 分、假记录、假课程填充空白 |
| `ERROR` | 技术失败、网络失败、解析失败或结果未知 | 重试、保留输入/草稿、查看可理解错误 | 将技术错误显示为学生业务无效 |
| `FORBIDDEN` | 身份、成员状态或权限不允许当前动作 | 返回允许入口、重新验证身份 | 模糊成网络错误，或绕过权限继续写入 |
| `MAINTENANCE` | 系统处于维护模式；未结束的补证计时暂停 | 查看说明、查看服务器确认的补证剩余时间、按系统事实重试 | 倒计时结束后本地自行恢复、维护期间自动逾期或重新发放完整窗口 |
| `RESUME` | 页面、会话、表单或上传因中断可恢复 | 继续、查看恢复范围、安全放弃（需要确认时） | 丢失已接受批次、重复提交、假定已经成功 |

所有 41 个页面都使用这一状态包络。对于没有列表的静态页，`EMPTY` 表示正文或远程内容不可用；对于没有可恢复写操作的只读页，`RESUME` 表示恢复到上次安全位置并重新核对事实，而不是虚构草稿。

## 3. 业务阶段不是通用 UI 状态

以下词语不得塞进 `LOADING` 或简单的成功/失败布尔值：

- 运动会话：`ACTIVE / PAUSED / COMPLETED`。
- 成员：`ACTIVE / PENDING`，其中学生端 `PENDING` 显示“已退班”。
- 记录处理：待 AI 检查、待教师复核、待补证、技术处理中、补证已接收/待教师复核、有效、无效；系统补证逾期形成无效结果但来源必须单列。
- 计入结果：有效且计入、有效但未计入、无效；三者不可互相替代。
- 入班结果：成功、同学期已有班、自然过期、宽限耗尽、撤销/关闭、权限拒绝、技术失败、结果未知。

这些业务阶段最终必须来自服务器/Contract。无 Backend 时只能作为明确标识的 UI 评审样例，不能写入正式业务模型。

## 4. 通用组件约定

下一实现阶段优先复用或补充以下 UI 构件：

- 页面级加载骨架；
- 行内加载指示；
- 空态卡片（标题、原因、可选安全动作）；
- `BNBUErrorPanel` 风格的错误卡片；
- 权限/成员受限卡片；
- 全屏维护门控；
- 中断恢复卡片（恢复对象、最后已知状态、继续/安全退出）；
- 本地评审数据横幅。

通用组件只定义视觉与交互，不计算分钟、不决定审核结果、不延长截止时间，也不修改成员状态。

## 5. 状态切换安全规则

1. `LOADING → ERROR` 保留可安全恢复的输入和媒体草稿。
2. `LOADING → NORMAL` 只在取得明确结果后发生；超时不得默认成功。
3. `ERROR → LOADING` 的重试必须避免重复创建入班、提交或上传批次。
4. 任意状态收到维护事实后进入 `MAINTENANCE`；未结束补证计时暂停并显示服务器剩余时间；恢复 NORMAL 时重新查询、按剩余时间续计，不回放危险写操作。
5. 进程重启进入 `RESUME` 时先说明将恢复什么，再继续会话或上传。
6. `FORBIDDEN` 不得显示仍可点击的主写操作。
7. 补充截止、邀请宽限和游泳时限不得仅依靠设备时钟作最终判断。

## 6. 评审证据要求

每个页面至少提供 `NORMAL` 和其关键异常状态；每个页面组必须共同覆盖七状态。重点逐页截图对象为：

- 020–025 五个主导航与通知；
- 030–035 完整入班结果；
- 040–043 会话、材料、续传及游泳异常；
- 050–052 记录与原始体测；
- 060–061 一次补充；
- 070 免测/认证边界。

截图必须使用虚构样例，注明设计版本、分支、Commit、主题、语言、设备尺寸和状态；截图本身不能作为接口或功能验收证据。
