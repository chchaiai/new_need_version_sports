## 3. DATA_MIGRATION_DECISION_REQUIRED 门禁

**G2-06。** 只读盘点发现任何相关既有业务数据或不可解释的历史结构，即进入 `DATA_MIGRATION_DECISION_REQUIRED`：停止自动生成回填映射和后续执行，记录受影响对象、数量、缺失事实、可审计来源候选及待决项，交业务负责人确认。没有明确批准的逐行可审计来源、人工核验方案或数据清理方案，不得自动回填。目标叫 dev/test、不属于本仓库或开发者认为是旧数据，都不能跳过门禁。〔来源：任务 G2；旧设计 §5.6；总览 §4.1/4.9/11.2/11.3/23。〕

**G2-07。** 以下都不能作为猜测性迁移依据：

- 根据课程、组织或队名、关键词、旧 `applicationSubtype`、旧 subtype 或默认值补 `certification_kind`；认证分类与认可分钟仍由原 Owner 提供。
- 用旧 `credited_minutes` 的 0/60/120 值反推 ACTIVE 秒、日期、周或新门槛；同一阶梯值对应多个实际时长，不能无损反推。
- 给全部旧记录默认套用当前模板或目标，伪造历史统一规则版本；模板变更不追溯。
- 将旧单包媒体复制成两份物理资产，按文件名或 checksum 相等就推断补证，或伪造前后阶段、审核轮次与服务器受理时间。
- 为自然到期的旧邀请默认生成到期前登记事实；本地草稿和访问日志片段不能自动等同合法注册流程登记。
- 为已关闭/归档数据补造结算、删除积压、批量判无效，或把旧统计求和结果直接当作新计入选择与结算报告。

〔来源：BD-20260903-04/06/07/08/09/10、BD-20260904-01/02；AT-09～14、16、19/20、23～25；总览 §8/9.4/11.2～11.5/12.3/21；旧设计 §5.3/5.4/5.6/5.7；G2-06。〕

**G2-08。** 迁移决定至少回答每类缺失事实用什么来源、由谁核验、哪些行无法确定、怎样保留旧值和映射记录、怎样验证新旧口径差异。无法确认的行保留待决，不填默认值掩盖未知，不把 Mock/fixture 当审计来源。新旧结果不同须区分 V8.1 公式变化、历史事实更正与技术计算错误，不能统一改成相同数值以凑对账。〔来源：旧设计 §5.6；总览 §11.3/12.3/21；任务 G2；A 的规则与事实分离。〕

## 5. 备份、恢复与回退边界

**G2-12。** 有既有数据时，在任何获准写入之前先确认可恢复备份及一致性边界：数据库 schema/事实行、历史版本与 current pointer、审核/计时关联、媒体对象与 manifest、迁移映射和审计序列应对应同一受控恢复点。外部媒体不能只备份数据库 URL；签名 URL 不是持久资产。备份权限、保管与演练环境由环境负责人另定，本稿不指定未经批准的目标、RPO/RTO、保留天数或恢复成功时间。〔来源：总览 §4.9/4.12/19/21；旧设计 §5.4/7.1；任务 G2。〕

**G2-13。** 首个空库初始化尚未开放业务写入且空库证据仍成立时，可在授权范围内恢复到初始化前状态或重建该空环境；一旦出现正式事实，不能继续按空库处理。Migration 事务失败只回滚该事务数据库写入，不表示 COS 资产、通知或其他已提交事务全部自动恢复；未绑定素材清理沿用原媒体生命周期，不删除正式绑定历史。〔来源：旧设计 §5.4/7.1/7.5；总览 §4.9；任务 G2。〕

**G2-14。** 新模型已开始业务写入后，禁止将 35/45/59 等分钟降格为旧 0/60/120 阶梯、合并同日真实记录、丢弃材料版本，或抹去结算/审核事实以兼容旧版。这些变换不可逆，不能承诺无损 down migration。应停止新的不兼容写入，由已授权方案选择向前修复，或在隔离环境恢复完整、兼容且经核验的数据库与媒体恢复点。恢复点之后已有正式事实时，先明确保留/重放和一致性核验方案，不能无声丢失。〔来源：BD-20260903-06/08/09、BD-20260904-02；AT-10/13/25；总览 §4.9/11.3/11.4/21；旧设计 §5.4/5.7/7.1。〕

**G2-15。** 技术恢复不能代替有权限教师改判、重新补证、重新结算或修改成绩。恢复后先核对历史引用、记录/素材关联、规则版本、计时/维护序列和原报告，再由各 Owner 公开能力重建派生投影；current pointer 不得指到其他对象的历史版本。B/F 时间恢复语义只引用 P4-H，不在 G2 建立另一套暂停、续计或错误逾期补救规则。〔来源：BD-20260904-02；AT-13/23/25；总览 §4.12/12.3/18/21；旧设计 §5.3/5.4/5.7；模块边界 §1/4/6。〕

### 5.1 恢复输入完整性与停止条件补强

**G2-15A（恢复清单）。** G2-12的同一受控恢复点应有可核对的证据清单：环境与schema版本、恢复点身份、原规则与统计策略版本、各Owner事实/集合版本、A选择检查点及其前驱/输入引用、E报告版本及其历史成员范围、C材料版本到持久媒体对象的关联。摘要或校验值只用于验证对应内容未混用，不证明业务合法，也不能按内容相同推断新的补证关系。正式原件仍在受控存储，不将学生资料或凭据复制到本稿。B/F计时和维护恢复所需事实由其Owner指明，本清单只登记正式引用，不创设另一个计时结构。〔来源：G2-12/15；P4-Z设计A-19/19A/22、C-01～03、E-08A/E-10A；BD-20260903-06/08/09、BD-20260904-02；AT-13/19～21/23/25；总览§4.9/4.12/11.4/18/21；旧设计§5.4/5.7/7.1；模块边界§4。〕

**G2-15B（核对顺序）。** 获授权后的恢复方案须先在隔离范围还原并核对原事实与历史引用，确认对象归属、规则/版本关联、历史报告范围、媒体实际可用及恢复点后的事实处置完整，再由各Owner能力恢复所需派生结果。A能重建缓存不代表E原报告可以重新生成后冒充原版；应先核对原报告及其输入，缓存刷新只更新派生投影。用最新事实重算出的总数与备份相等，也不能证明恢复了原选择组合或原报告。公开服务的恢复条件另经执行方案确认；本稿没有批准恢复上线、选择数据丢弃范围或重发通知。〔来源：G2-10/12/14/15；P4-Z设计A-19A、A-RECOVERY-VERIFY、E-08/E-10A；BD-20260903-08/09、BD-20260904-02；AT-13/25；总览§4.9/21；旧设计§5.7/7.1；模块边界§4/6。〕

**G2-15C（停止与归属）。** 任一必要原事实、持久对象、规则版本、报告历史范围或计时来源缺失/冲突时，停止受影响恢复核验并交相应Owner；不得靠默认版本、猜测日期、补造素材或重置倒计时补齐。A检查点缺失时，仅在有完整且顺序明确的输入与前驱链可按A-19A重建后，才能声称恢复同一选择；两者都缺失须保留待恢复。恢复点之后的正式事实处置未确定时，也不能跳过它们宣称完整恢复。这些是恢复证据缺项；若涉及未知旧数据向新结构映射，则另触发G2-06的 `DATA_MIGRATION_DECISION_REQUIRED`，不把技术缺项自行转成业务改判授权。〔来源：G2-06～08/14/15；P4-Z设计A-19A/A-RECOVERY-VERIFY；BD-20260903-08、BD-20260904-02；AT-13/25；总览§4.9/12.3/18/21；旧设计§5.6/5.7/7.1；任务G2；ISS-017见P4-Z问题记录。〕

**G2-15D（定向评审情形）。** 本轮补充八项文字推演，作为未来演练的判据，不是恢复测试通过：①完整来源、引用、持久对象、A前驱与E原报告均可核对，才可进入后续受控重算；②总量相同但A检查点和重放链均缺失，不能声明原选择已恢复；③前驱链断裂，不能伪造空根；④缓存重算覆盖原报告内容，即使总数没变也不是合法历史恢复；⑤只恢复数据库URL、对应媒体对象缺失，恢复不完整；⑥来源来自不同恢复点、无法给出一致快照，不进入当前投影发布；⑦恢复点后已有事实而处置未明确，不静默舍弃；⑧B/F所需计时来源缺失，等待其Owner，G2不自行补算。情形②的具体统计反例已由A-RECOVERY-VERIFY内存算术核对；其他情形仅为文档约束推演，数据库、媒体、日志重放及恢复上线均NOT EXECUTED。〔来源：G2-12～15C；P4-Z设计A-19A/A-RECOVERY-VERIFY、E-08A～08D；AT-13/19/23/25；总览§4.9/11.4/18/21；旧设计§5.4/5.7/7.1；本轮定向Review。〕
