# BNBU Sports 管理员端业务流程（Web）

> **文档版本**：v7.19
> **更新日期**：2026-09-01
> **文档范围**：本文只描述管理员的业务职责、管理流程、状态变化和安全边界，不记录技术实现细节。
> **业务决策说明**：本文记录用户确认的目标业务规则，不表示当前产品已经全部实现。
> **Phase 3 上线状态**：本文件所述正式管理员能力全部进入上线范围，不允许以空表、占位状态、Mock 或 Fake Success 代替

## 1. 管理员端定位

管理员负责只读查看当前全部课程及其学生和打卡汇总、只读查看学生账户资料与状态，并管理学期、教师账号、管理员权限、用户反馈、全局规则、系统模式、帮助中心和审计查询。

管理员基础角色只有一种，但分为：

- 总管理员：系统初始治理负责人，拥有全部管理员权限；
- 分管理员：由总管理员建立，并按被分配的权限处理指定业务。

管理员不能创建或管理课程，也不能默认代替责任教师处理课程成员、打卡、耐力跑、认证或成绩发布。

上线版本中，管理员必须具备本文明确的学期、用户与账号、分管理员治理、反馈、全局规则、系统模式、帮助中心和审计能力，并只读查看当前课程。教师仍负责创建本人班级、邀请码和教学审核；管理员不能代替，学生也不能自行创建或自由选择班级。

当前课程查看和审计日志本身是只读能力；除此之外，管理员职责范围内的业务应提供真实管理动作，不以永久只读作为默认设计。

## 2. 管理能力总表

| 业务域 | 正式管理动作 |
|---|---|
| 系统概览 | 查看当前学期、系统模式、课程和待处理事项摘要 |
| 当前课程 | 只读查看全部当前课程、课程详情、学生人数和打卡情况 |
| 学期管理 | 创建、修改即将开始的学期，并通过切换设定唯一当前学期；旧当前学期自动归档 |
| 学生账户 | 按学号、姓名、学院/部门、班级和状态查询学生资料并查看详情；全程只读 |
| 教师账号 | 校验 UTF-8 CSV 后批量建立教师账号、设置统一初始密码、核对后删除教师登录账号 |
| 管理员治理 | 总管理员创建、编辑、停用、启用或删除分管理员，并分配或收回权限 |
| 用户反馈 | 查看汇总、搜索筛选、受理、更新状态、公开回复、关闭和重新跟进 |
| 全局规则 | 选择并维护四套 1000/800 米换算表，不审批单个学生最终成绩 |
| 系统模式 | 在正常和维护模式间受控切换 |
| 帮助中心 | 创建草稿、编辑、发布、下线和重新上线面向学生的中英双语帮助文章 |
| 审计日志 | 查询审计事件、查看脱敏详情，并按授权日期范围请求服务器运行日志 ZIP |
| 本人账号 | 本人改密、密码找回、退出登录；分管理员在无职责阻塞时可以注销本人账号 |

单个学生最终成绩由责任教师填写和发布。管理员不代替教师输入成绩，也不审批教师填写的最终成绩。

## 3. 管理员通用规则

- 分管理员只能处理被总管理员授权的业务范围；
- 总管理员仍受责任教师和历史保留边界限制；
- 数据已经更新时，先查看最新状态再重新确认；
- 重复点击不能重复创建或重复执行同一结果；
- 高影响操作必须显示影响范围并要求再次确认；
- 关键操作保留操作者、时间、原因、对象和结果；
- 操作失败时原状态保持不变；
- 密码和验证码不得进入普通业务记录；
- 审计历史不能被任何管理员修改或删除。

## 4. 管理员层级与权限

### 4.1 初始总管理员

系统初始只有一名总管理员。

初始总管理员由系统或他人分配的初始密码属于临时密码。首次登录后只能修改本人密码或退出登录，完成本人改密前不能进入其他管理员业务；本决定不为初始总管理员的初始密码补造此前未确认的长度或字符组合规则。

总管理员拥有以下治理权限：

- 当前课程只读查看；
- 学期；
- 学生账户只读查看；
- 教师账号；
- 分管理员；
- 用户反馈；
- 全局规则；
- 系统模式；
- 帮助中心；
- 审计查询；

总管理员仍受责任教师边界和历史保留规则限制，不能创建或管理课程，也不能代替教师处理教学业务。

分管理员设置页顶部展示分管理员总数、状态为 `ACTIVE` 的已启用数量，以及当前固定的 8 项可分配业务权限数量。三项数字都是管理员治理摘要，不代表普通学生、教师账号数量，也不包含自动可见的系统概览或禁止下放的分管理员设置。

### 4.2 创建和编辑分管理员

创建时，总管理员选择一个已完成身份核验的人员，填写全系统唯一且创建后不可修改的账号、姓名、有效且未被其他分管理员使用的学校邮箱和可选所属部门，并设置初始密码和确认密码。初始密码只要求已填写且两次输入一致，不额外规定长度、字符组合、强度提示或自动生成规则，不得把 Portal 的 12 位限制或教师批量建立账号的初始密码规则套用到分管理员。

该初始密码属于由他人分配的临时密码。分管理员首次登录后只能修改本人密码或退出登录，完成本人改密前不能进入其他管理员业务；成功改密后清除首次改密门禁。

创建前必须集中展示账号资料和即将分配的全部业务权限，供总管理员完成最后核对；至少选择一项业务权限后才能创建。创建成功后账号状态默认为 `ACTIVE`。系统概览根据已分配权限自动展示，不作为单独权限；分管理员设置永远不能下放。

总管理员可以先选择职责模板，再继续增减具体权限。模板只用于快速填写，不限制自定义组合权限，选择新模板会覆盖当前勾选结果：

- 学生服务：学生问题反馈、帮助中心、审计查询；
- 教务运营：课程查看、学期管理、用户与账号；
- 规则与系统：全局规则、系统模式、审计查询；
- 只读核查：课程查看、审计查询。

可分配权限：

| 权限范围 | 可执行事项 |
|---|---|
| 当前课程 | 只读查看课程详情、学生人数和打卡情况 |
| 学期 | 创建、修改即将开始的学期并切换当前学期；切换自动归档旧当前学期 |
| 用户与账号 | 只读搜索、筛选和查看学生资料及当前状态；批量建立和删除教师账号 |
| 用户反馈 | 查询详情、更新处理状态、追加公开回复、关闭和重新跟进反馈 |
| 全局规则 | 查看四套 1000/800 米换算表，添加、编辑或删除用时区间规则 |
| 系统模式 | 切换正常和维护模式 |
| 帮助中心 | 创建、编辑、发布、下线和重新上线帮助文章 |
| 审计查询 | 查询审计事件、查看脱敏详情，并按授权日期范围请求服务器运行日志 ZIP |

可分配业务权限固定为 8 项：课程查看、学期管理、用户与账号、学生问题反馈、全局规则、系统模式、帮助中心和审计查询。权限不要求套用固定套餐，但不能包含创建或授权其他管理员的能力，也不能包含责任教师专属业务。只有总管理员可以创建分管理员或更改分管理员权限；分管理员不能创建、提升或授权其他管理员。学期管理、全局规则和系统模式属于高风险权限，创建或编辑确认时必须明确标识。

编辑时，登录账号保持不可修改；姓名、学校邮箱、所属部门和业务权限可以更新，学校邮箱仍须有效且唯一。普通资料编辑不显示或接收新密码和确认密码，保存前只显示更新后的身份、权限数量和高风险权限摘要。

总管理员不能查看、取得或替换分管理员的个人密码，也不能在普通资料编辑或独立应急流程中代设密码。分管理员个人密码只允许本人改密或通过已验证学校邮箱自助重置；这一边界同样不允许代设教师密码或绕过停用状态。

### 4.3 启用与停用分管理员

分管理员账号只有 `ACTIVE` 和 `DISABLED` 两种状态。创建成功后默认为 `ACTIVE`；总管理员可以在账号列表中停用或重新启用。停用前应完成职责移交；停用后：

- 分管理员不能继续登录；
- 所有设备退出登录；
- 已完成的操作历史继续保留；
- 停用操作本身不物理删除分管理员账号；只有第 4.4 节的删除或第 5.5 节的本人注销才物理删除账号相关数据。

重新启用后，只恢复该账号当前已经分配的业务权限，不自动恢复曾被收回的权限，也不新增任何权限。状态变化和更新时间必须进入审计历史。

### 4.4 删除分管理员

只有总管理员可以删除分管理员。删除确认框必须显示姓名、登录账号和学校邮箱供再次核对；执行前必须确认该管理员已经完成全部职责移交。

删除后，该账号从当前可用管理员列表中移除，不能继续登录；登录账号、密码凭据、现有登录会话、验证码/验证挑战、学校邮箱和当前管理员资料被删除。已经完成的业务记录和审计历史继续保留，并只关联不具登录能力且不含当前账号资料的内部历史主体标识，不得借历史事实恢复账号。

### 4.5 当前不处理的总管理员场景

当前业务流程不处理总管理员离任、失联、本人注销或身份交接。总管理员忘记密码无法登录时，可以通过已验证学校邮箱完成本人验证并设置新密码。

## 5. 登录与本人账号

### 5.1 登录

总管理员使用已验证学校邮箱和本人密码登录；分管理员使用总管理员建立的唯一账号和本人密码登录。分管理员的学校邮箱用于身份核验和密码找回，不代替其登录账号。

系统确认账号有效且属于管理员后，才允许进入与本人权限对应的工作台。

### 5.2 密码找回

总管理员和分管理员都可以通过已验证学校邮箱完成本人验证并设置新密码。密码更新后，旧登录状态全部失效。

密码找回只服务管理员本人，使用已验证学校邮箱的 `PASSWORD_RESET` 一次性验证挑战，页面不要求组织代码；挑战请求统一返回反枚举外观。验证成功后设置的新个人密码只要求非空，全部旧登录状态失效，系统不自动登录，并清除首次改密门禁。状态为 `DISABLED` 的账号不能借重置恢复访问，并在验证证明有效后返回稳定停用错误；已删除账号继续保持反枚举失败，不能通过找回恢复。

密码内容、验证码和 Token 不进入普通日志、业务记录或审计事件；审计只记录不含秘密的安全动作、结果和请求标识。现有凭据错误、挑战过期、账号停用、首次改密门禁、版本冲突和限流错误继续使用；非空 request 校验继续使用既有请求校验错误。

### 5.3 日常本人改密

状态为 `ACTIVE` 的总管理员和分管理员可以在有效登录状态下凭当前密码和最新数据版本修改本人密码，不需要任何管理员业务权限；维护模式仍允许该安全动作。新个人密码只要求非空。成功后其他登录状态全部失效，当前登录状态继续有效，并清除首次改密门禁。

个人新密码不设置最大长度、弱密码名单或必须不同于当前密码的额外业务限制；不新增 `PASSWORD_POLICY_VIOLATION`，也不使用 `TOO_LONG / BLOCKLISTED / SAME_AS_CURRENT`。

### 5.4 退出登录

退出登录后，当前设备的登录状态失效。

### 5.5 分管理员注销本人账号

分管理员可以申请注销本人账号，但必须先完成或移交全部职责。

注销后：

- 登录账号、密码凭据、现有登录会话、验证码/验证挑战、学校邮箱和当前管理员资料被删除；
- 所有设备退出登录，原账号不能继续登录或被静默恢复；
- 审计和业务历史继续保留，并只关联不具登录能力且不含当前账号资料的内部历史主体标识。

总管理员不适用该流程。

## 6. 系统概览

系统概览根据当前管理员权限展示：

- 当前系统模式及最后变更时间；
- 唯一当前学期及日期范围；
- 学生总数、状态为 `ACTIVE` 的学生数、行政班级去重数量及已有班级资料的学生数；
- 教师总数；
- 最近一次系统健康检查时间，以及 API、数据库、站内通知中心、对象存储和媒体存储状态；
- 1000/800 米换算表已配置规则数量和适用分组数量。

学生和行政班级摘要来自当前管理空间的账户资料，不等同于课程目录中的有效课程成员数。

不具备某项权限的分管理员不能通过概览进入对应管理业务。

系统概览和系统健康检查均为只读观察能力：刷新只能重新取得状态，不能改变业务事实。健康状态使用 `UP`、`DOWN`、`NOT_CONFIGURED` 等明确结果；延迟、积压数量或检查结果缺失时显示不可用，不能显示 `undefined` 或推断服务健康。概览中的数量和摘要只用于导航与风险提示，不能代替各业务页面的正式数据和权限校验。

概览卡片只能进入对应业务页面，不能绕过该页面的权限与动作边界。

## 7. 当前课程只读查看

管理员可以通过“课程目录看板”查看当前学期未关闭课程。这里的课程由责任教师在当前学期自定义创建并命名；管理员只能刷新、搜索、筛选和展开详情，不能创建、编辑、关闭、删除或恢复课程。

看板顶部固定展示三项只读汇总：当前课程数（当前学期未关闭课程）、总学生数（当前课程有效成员去重）和总教师数（当前课程责任教师去重）。这些数字只反映当前看板范围，不能与全校用户总数、历史成员数或课程次数混用。

### 7.1 课程列表

课程列表至少展示：

- 教师自定义的课程名称；课程代码和教学班号不属于管理员端业务信息；
- 当前学期；
- 责任教师；
- 目录展示状态：`UPCOMING`（即将开始）或 `ACTIVE`（进行中）；
- 允许打卡的日期或时间范围；
- 课程相关运动目标和其他运动目标；
- 学生人数；
- 已提交打卡的学生人数；
- 打卡记录总数、有效记录数和无效记录数；
- 累计计入时长。

管理员可以按课程名称或责任教师关键词搜索，并筛选全部、进行中或即将开始课程；也可以打开课程详情查看上述数据，但这些查看动作不能改变课程事实。课程目录不设置“已结束”业务状态，也不提供“已结束”筛选或标签。

当前课程目录没有完成全部目标学生人数这一正式字段，因此“完成全部打卡学生占比”必须显示不可用；未来只有在正式数据同时提供完成学生人数和可比较分母后才能展示，仍不得用提交人数、有效记录数或计入时长推算。

### 7.2 课程详情和统计口径

学生人数以当前有效课程成员为主要口径，并单独展示已移出人数；已提交学生按当前看板范围去重。打卡汇总区分有效和无效记录。每名学生先按本人两类目标分别封顶并得到本人总有效学时，课程累计计入时长再汇总这些学生级总有效学时；人均计入时长以课程累计计入时长除以有效成员数计算，有效成员为 0 时显示 0。展开详情还展示当前学期、责任教师、允许打卡时间、课程相关目标、其他运动目标和入班开放/关闭状态。

上线学时统计累计当前审核结果为 `VALID` 的 Record 和当前有效的认证认可学时；每条 Record 根据 Backend 确认的正式实际运动时长映射为 0、60 或 120 分钟计入有效学时，`INVALID` Record 与已撤销认证不计入任何学时统计。对每名学生，每个运动类别独立累计并按本类别目标上限封顶，再相加得到该生总有效学时。该生课程完成率为 `min(总有效学时 / 总目标学时, 100%)`；UI 四舍五入为整数百分比，但全部业务判断使用原始分钟值。课程级累计和人均结果只能在学生级封顶后汇总，不能先合并全班事实再统一封顶。

同一学生、同一教学班的业务日期固定为 Backend 接受 Session 开始命令时 `started_at` 在上海时区的日历日期。Session 跨午夜、暂停、结束或延迟提交都不改变该日期；管理员只读汇总不得按提交日期重新归属 Record。

课程目录只提供课程级汇总和展开摘要，不提供单个学生名单、单条打卡详情或图片/视频凭证入口。需要处理课程成员、打卡记录、媒体、审核、认证或成绩时，仍由责任教师进入其业务页面处理，管理员不能从该看板下钻后改写。

管理员不能通过课程详情执行以下动作：

- 创建、编辑、关闭、恢复或删除课程；
- 修改责任教师、课程成员或官方名单；
- 设置两类运动目标或允许打卡时间；
- 生成课程邀请；
- 修改打卡结果、正式时长、认证或成绩。

上述课程业务由责任教师处理，管理员只查看整体运行情况。

系统不设置教师内部备注。打卡、免测和认证审核只保留正式结果、学生可见原因或学生可见处理意见；管理员只读页面也不展示或补写额外隐藏备注。

## 8. 学期管理

### 8.1 学期状态

学期依次经历以下单向生命周期：

即将开始 → 当前学期 → 已归档

系统同时只能有一个当前学期。当前状态只能由一次学期切换产生；已归档学期不能恢复，也不能物理删除。页面以 `UPCOMING`、`CURRENT`、`ARCHIVED` 展示三种状态。

学期管理页汇总当前学期及日期范围、可继续编辑配置的即将开始数量和永久保留历史的已归档数量。全部学期列表展示名称、学年、日期范围、课程/学生摘要、状态及当前允许的操作；这里的课程/学生数字是该学期摘要，不能替代课程目录或学生账户的正式明细。

### 8.2 创建学期

具有学期权限的管理员填写学年、学期、显示名称、开始日期和结束日期。

学年必须使用连续学年的 `YYYY-YYYY` 格式，后一年度等于前一年度加一；学年和学期组合不能重复，结束日期不能早于开始日期。新学期进入 `UPCOMING` 状态，课程数和学生数初始为 0。

### 8.3 修改即将开始的学期

只有 `UPCOMING` 学期可编辑配置；`CURRENT` 和 `ARCHIVED` 学期只读。编辑范围为显示名称、学年、学期类型和日期范围；保存前仍须校验学年与学期组合唯一、日期顺序及当前最新版本，冲突时不得覆盖。

### 8.4 切换当前学期

1. 选择一个 `UPCOMING` 学期；
2. 确认目标学期已经到达开始日期；尚未到达时拒绝切换；
3. 在确认框中核对原当前学期和新当前学期；
4. 确认切换；
5. 原当前学期自动变为 `ARCHIVED`；
6. 新学期成为全系统唯一 `CURRENT` 学期；
7. 保存完整切换记录。

管理员不能通过单独“归档当前学期”的操作结束当前学期，也不能把归档学期恢复为当前。归档只由成功切换产生，且不删除教学班、成员、打卡、审核、申请或成绩历史。

## 9. 教师账号管理

教师账户列表展示工号、姓名、职称、学院/部门、部门和当前账号状态；详情只读展示用户标识、组织标识、学院/部门、部门、职称、状态、更新时间和数据版本。`ACTIVE`、`DISABLED`、`RECOVERY_REQUIRED` 在这里都是状态信息，“用户与账号”页面不提供教师账号的停用、启用或恢复审批操作。

### 9.1 批量建立教师账号

具有教师账号权限的管理员可以上传或粘贴 UTF-8 CSV，一次录入多名教师，并为本批账号设置同一个初始密码。学生账户不得通过该入口创建。

CSV 必填列为 `employee_id`、`name`、`email`，`college` 为可选列。正式建立前必须先生成校验预览，逐行确认必填字段、学校邮箱格式、工号和邮箱唯一性以及与现有账号的冲突；任一行有错误时整批不能确认建立。

录入前确认：

- 邮箱是有效的学校邮箱；
- 每个邮箱对应一名真实教师；
- 重复或冲突邮箱不能重复建立账号；
- 初始密码至少 8 位并同时包含大写字母、小写字母和数字；
- 统一初始密码通过受控方式告知教师；
- CSV 模板和导入文件不得包含初始密码；
- 账号建立完成后系统不再展示初始密码，普通文档和业务记录也不得保存密码明文。

### 9.2 教师首次登录与改密

教师使用学校邮箱和统一初始密码首次登录。

教师首次登录后必须立即设置个人密码；完成改密前不能进入其他教师业务。更改后的密码只属于教师本人，管理员不能查看。

教师设置的新个人密码只要求非空，不继承批量初始密码的长度和字符组合要求；成功后清除首次改密门禁。管理员不能代设教师个人密码。

### 9.3 删除教师账号

管理员填写删除原因并再次输入教师工号确认后，可以删除教师登录账号。

删除教师账号不以责任教师交接为前置，也不建立责任教师交接业务。管理员不能借账号删除修改或转移课程责任教师、管理课程或改写课程事实；账号删除与课程事实变更是两个不同边界。

删除后：

- 教师不能继续登录，所有设备的有效登录状态失效；
- 登录账号、密码凭据、现有登录会话、验证码/验证挑战、学校邮箱和当前教师资料被删除，不再出现在当前教师账户列表；
- 已有教学班、学生课程关系、运动记录、正式媒体、审核、成绩和审计历史继续保留，并继续引用不具登录能力且不含当前账号资料的内部历史主体标识；
- 历史责任教师信息按业务发生时的快照保留，不能因账号删除而改写；
- 删除操作写入审计记录，不能从普通页面恢复；
- 教师以后重新入职时必须建立新账号，新账号不能覆盖原账号历史。

## 10. 学生账户只读查看

管理员可以在学生账户页刷新数据，按学生姓名、学号、学院、专业或行政班级关键词搜索，按账号状态和学院/部门筛选，并分页查看结果。列表至少展示学号、姓名、学院/部门、行政班级和当前状态。

学生详情只读展示业务核查所需的用户标识、组织标识、性别、年级、学院/部门、专业、行政班级、学生状态、更新时间和数据版本。管理员不能从列表或详情修改学生姓名、学号、性别、年级、学院、专业、班级、角色、邮箱、学生状态、课程关系或登录状态。

学生状态只有 `ACTIVE` 和 `PENDING`：`ACTIVE` 表示学生已进班；`PENDING` 表示学生已经绑定并验证学校邮箱，但已退班且当前没有有效体育教学班。学生列表和详情不得显示 `RECOVERY_REQUIRED`、`DISABLED` 或其他学生状态。当前“用户与账号”页面不提供恢复申请核验、批准、驳回、改绑邮箱、停用、恢复或撤销登录的操作，也不得通过详情页绕过这一边界。

管理员不能查看用户当前个人密码。统一教师初始密码只用于批量建立教师账号，不等于管理员可以查看教师修改后的个人密码。

## 11. 用户反馈管理

Android 与网页学生端统一提交问题类型（功能异常、功能建议、无障碍问题、隐私问题、其他）和问题描述。系统把反馈与已登录学生身份关联，生成反馈编号、提交时间和初始状态“待受理”。管理端按同一分类与问题内容展示，并补充提交人姓名、学号和当前学校邮箱。客户端平台、版本、附件、优先级、指定处理人和内部备注不属于当前管理界面的业务字段。

所有来源为学生的反馈统一进入管理员队列。只有具有“学生问题反馈”权限的管理员可以进入该业务范围；教师没有管理端反馈单的查看、回复或状态修改权限。

### 11.1 概况、查询与列表

页面顶部展示三项可点击概况：学生反馈总数及其中的待处理数量、待技术团队处理数量、处理完成数量。“待处理”包括待受理、受理中和待技术团队处理，不包括处理完成或已关闭；点击概况只改变当前列表筛选，不改变任何反馈事实。

管理员可以按反馈编号、提交人姓名、学号、当前学校邮箱、分类或问题内容搜索，按全部、功能异常、功能建议、无障碍问题、隐私问题或其他筛选问题类型，并按全部、待受理、受理中、待技术团队处理、处理完成或已关闭筛选状态。搜索、筛选、清除筛选、翻页和刷新都属于只读操作；列表每页最多展示 6 条。

列表展示反馈编号、提交人姓名、学号、当前学校邮箱、问题分类、问题摘要、提交时间、当前状态和详情入口。找不到结果时显示空状态，不得把无结果解释为反馈已删除。

详情展示反馈编号、分类、提交时间、提交人姓名、学号、当前学校邮箱、当前状态、完整问题内容，以及已有处理记录。每条处理记录至少保留处理人、公开回复内容和处理时间。

### 11.2 反馈状态

| 状态 | 业务含义 | 可否由处理表单选择 |
|---|---|---|
| 待受理 | 学生刚提交、尚未开始处理的初始状态 | 否 |
| 受理中 | 管理员已经受理并正在跟进 | 是 |
| 待技术团队处理 | 问题需要技术团队继续排查或处理 | 是 |
| 处理完成 | 已经向学生说明处理结果，当前无需继续处理 | 是 |
| 已关闭 | 本轮反馈已经关闭 | 是 |

待受理反馈首次打开处理表单时，默认选择受理中。处理状态不是固定的单向审批链：管理员保存时可以在受理中、待技术团队处理、处理完成和已关闭之间选择当前状态；待受理不能被重新选择。处理完成或已关闭后确需继续跟进时，可以重新设为受理中或待技术团队处理，但必须通过新增公开回复说明原因和下一步。

### 11.3 处理、回复与留痕

1. 管理员从列表打开反馈详情，核对提交人、分类、问题内容、当前状态和既有处理记录；
2. 管理员选择本次保存后的状态；待受理反馈默认选择受理中；
3. 管理员必须填写学生可见的公开回复，说明处理结果或下一步，空白回复不能保存；
4. 保存后系统更新当前状态，并追加一条包含处理人、回复内容和处理时间的记录；
5. 系统记录状态变更前后值和本次回复的审计信息；已有处理记录不得覆盖、改写或删除。

“待技术团队处理”只表示当前处理状态，不等于系统已经建立技术人员账号、工单指派或自动通知。课程问题需要教学事实时，管理员可以另行协调对应责任教师核查，但当前反馈界面不提供“转交责任教师”、指定处理人或教师处理入口；反馈单、状态和公开回复始终由管理员负责。

当前页面不提供删除反馈、删除回复、编辑既有处理记录或内部备注的动作。管理员不得在公开回复中写入密码、验证码、访问令牌、完整身份资料或其他不应向学生公开的内部信息。

反馈处理不能直接改写课程成员、打卡审核、耐力跑、认证、成绩、申请、账户状态或课程关系。确需修正正式业务事实时，必须回到对应业务流程并由有权限的角色操作；反馈记录只负责沟通和跟踪。

## 12. 全局规则与最终成绩边界

### 12.1 页面范围与权限

当前“全局规则”页面只维护 1000/800 米耐力跑换算表。20 小时运动进度仍按已确认的固定业务规则计算，不在本页创建、修改、启用或停用；责任教师填写的最终成绩也不在本页审批或修改。

只有具有“全局规则”权限的管理员可以进入并修改换算表。该权限属于高风险权限，但每次添加、编辑或删除由当前有权限的管理员确认后直接处理；页面不提供单独的规则启用、停用、提交审批、二次批准或批量发布操作。

### 12.2 四套换算表

换算表按性别、年级组和项目固定为四套：

| 换算表 | 项目 | 当前 100 分区间 | 当前 0 分区间 |
|---|---|---|---|
| 男 · 大一 / 大二 | 1000 米 | 0–239 秒 | 537–600 秒 |
| 男 · 大三 / 大四 | 1000 米 | 0–249 秒 | 547–600 秒 |
| 女 · 大一 / 大二 | 800 米 | 0–229 秒 | 527–600 秒 |
| 女 · 大三 / 大四 | 800 米 | 0–239 秒 | 537–600 秒 |

切换“换算表选择”只改变当前查看和维护的表，不修改任何规则。男生不能配置 800 米表，女生不能配置 1000 米表；大一/大二和大三/大四分别维护，不能跨组共用一张表。

当前预置数据每套表有 101 条规则，共 404 条。100 分和 0 分覆盖首尾区间，99 分至 1 分均为连续 3 秒一档、每档下降 1 分。等级口径为：95–100 分优秀、92–94 分良好、60–91 分及格、0–59 分不及格；100 分区间的默认备注为“国家学生体质健康标准满分区间”，其余备注可为空。

### 12.3 规则行与整表校验

每条规则包含：

- 必填的用时下限和用时上限，均使用非负整数秒并按包含上下限的闭区间解释；
- 必填的整数分数，范围为 0 至 100；
- 必填等级，只能选择优秀、良好、及格或不及格；
- 可选备注；
- 所属性别、年级组和项目由当前换算表决定，添加或编辑表单不能改到其他表。

同一表内规则按用时下限从小到大显示。一个具体用时必须且只能命中一个区间；相邻区间必须首尾连续，不能有间隙、重叠或完全重复区间。新增、编辑和删除都必须重新校验所选整表；分数越高对应的用时不得更慢，等级必须与当前分数档一致。任何范围、分数、组合、连续性或等级冲突都必须阻止保存。

### 12.4 添加、编辑和删除

添加规则时，系统保持当前所选换算表，并预填在现有最后区间之后的连续用时范围、建议分数、不及格等级和空备注；管理员仍须核对全部必填字段。保存成功后新行加入当前表并参与整表排序和校验。

编辑规则时，表单带入原用时上下限、分数、等级和备注。管理员可以修改这些字段，但不能改变该行所属性别、年级组或项目；保存后不得造成相邻区间间隙、重叠或其他整表冲突。

删除前必须显示准确的用时区间、分数和等级并再次确认。删除后换算表为空或不再连续有效时必须阻止；页面不提供绕过完整性校验的强制删除。创建、编辑和删除都记录操作人、时间、变更前后内容和结果，已有学生历史换算结果不得被追溯重算或覆盖。

### 12.5 换算结果与教师最终成绩

责任教师确认学生真实用时后，系统根据学生性别、当前年级组和项目选择唯一表，再按整数秒匹配唯一闭区间，生成耐力跑分数和等级。无法唯一匹配时不得猜测或使用相邻分数，应报告规则表异常并停止生成结果。

管理员维护换算表不等于确认学生真实用时，也不能直接修改任何学生的换算结果。耐力跑换算分和等级不增加打卡总时长、不进入 20 小时运动进度参考，也不自动成为或改写最终成绩。责任教师仍可直接填写、修改和发布本人教学班学生的 `INT` 整数最终成绩，并可附带最多 50 个字符的可选备注；系统不额外限制最终成绩为 0 至 100，管理员不审批，历次发布结果继续保留。

耐力跑免测由责任教师按免测流程审核；批准免测的学生显示免测状态，不使用普通用时换算表生成分数或等级。管理员不能通过全局规则页面批准免测或为免测学生指定个人分数。

## 13. 系统模式管理

系统模式管理是正式管理员业务。只有总管理员或具有“系统模式”权限的分管理员可以操作；该权限属于高风险权限，不能由学生、教师或无此权限的管理员代行。

### 13.1 当前模式与业务效果

| 模式 | 枚举 | 业务效果 |
|---|---|---|
| 正常模式 | `NORMAL` | 全部已开放业务按既有身份、权限、资源归属和对象状态正常运行 |
| 维护模式 | `MAINTENANCE` | 暂停普通学生和教师的业务访问并展示维护公告；管理员控制台只保留当前模式、变更历史和模式切换等明确允许的安全治理能力 |

页面顶部展示当前模式名称与枚举、模式说明、策略版本和最后更新时间。“刷新状态”只重新取得当前模式事实，不修改模式、策略或其他业务数据。无权操作的管理员只能在授权范围内查看，不得通过页面地址或请求参数获得切换能力。

### 13.2 选择目标模式与确认切换

当前模式标记为已选中且不能再次作为目标；授权管理员只能选择另一种模式作为目标。选择后，弹窗先展示“当前模式 → 目标模式”。每次切换都必须填写非空变更原因，内容应说明切换原因、影响范围和恢复条件。

切换到正常模式时，确认弹窗只要求变更原因；切换到维护模式时，还必须同时填写中文公告标题、英文公告标题、中文公告正文、英文公告正文和预计恢复时间。任何必填内容缺失、目标与当前模式相同或校验失败时，都不得执行切换。

管理员点击“确认切换”后立即应用目标模式；点击“取消”、关闭弹窗、请求失败或执行失败均保持原模式，不得显示假成功，也不生成成功变更历史。成功后重新读取当前模式、策略版本和更新时间，确认服务端最终结果；重复提交不得生成重复切换或重复公告。

### 13.3 维护公告与恢复

切入维护模式时，中英文公告随模式切换同步发布，并在维护期间向受影响用户展示。预计恢复时间用于向用户告知计划，不是定时自动切回正常模式的指令；即使到达该时间，系统也继续保持当前模式，直到授权管理员明确执行下一次模式切换。

维护模式下，具有“系统模式”权限的管理员仍可进入必要的治理控制台并切换到正常模式，避免系统无法恢复；普通学生和教师只能看到维护公告，不能进入日常业务。切回正常模式时必须填写恢复原因，并向受影响用户生成“系统已恢复”辅助通知；通知是否送达不作为恢复成功依据，仍以重新取得的当前系统模式为准。

维护和恢复通知只进入站内通知中心，不发送短信、邮件或 Android/iOS 系统 Push。通知是否已读不改变当前系统模式或其他业务事实。

### 13.4 历史、审计与事实保护

每次成功切换追加一条只读历史，至少展示变更原因、变更前模式、变更后模式、操作人、变更时间，以及维护公告是否已发布。历史记录没有编辑或删除入口；审计记录继续保留，不能由系统模式页面补写、修改或删除。

模式切换只改变全局运行约束，不删除、覆盖、撤销或重算既有课程、成员、名单、打卡、审核、认证、免测、成绩、反馈、账号或审计事实。维护模式下只保留当前模式、变更历史和模式切换等明确允许的安全治理能力，不因此扩大其他管理写权限。学生、教师及无权管理员不能通过旧页面、缓存、本机时间或重复请求绕过当前模式。

## 14. 帮助中心管理

帮助中心管理是正式管理员业务。只有总管理员或具有“帮助中心”权限的分管理员可以进入授权范围并管理文章；页面维护的是面向学生的中英双语自助内容，不是教师帮助、用户反馈工单或实时维护公告。

### 14.1 概况、查询与列表

页面顶部按全部文章统计并展示三个可点击概况：已发布、草稿和已下线数量。点击概况只把对应状态设为当前筛选并回到第一页，不修改任何文章；概况数字不随当前搜索或分类筛选缩小。

管理员可以按中英文标题或关键词搜索，按全部、已发布、草稿、已下线筛选状态，并按以下固定分类筛选：

- 登录与验证码；
- 加入课程与补正；
- 打卡与学时；
- 凭证上传；
- 课程与成绩；
- 免测；
- 组织认证；
- 通知；
- 维护期间操作；
- 服务反馈。

搜索、状态筛选、分类筛选或清空筛选后都回到第一页。列表按排序权重从高到低排列，权重相同时按最后更新时间从新到旧排列，每页最多展示 5 条；每条展示状态、分类、更新时间、当前管理界面语言对应的标题与正文、全部关键词及当前允许的操作。搜索、筛选、翻页和预览都是只读操作。

### 14.2 文章状态与允许动作

| 中文状态 | 状态值 | 允许的后续动作 | 学生可见性 |
|---|---|---|---|
| 草稿 | `draft` | 编辑、保存当前草稿、发布 | 不公开 |
| 已发布 | `published` | 编辑并保存当前公开内容、下线 | 当前语言投影对学生公开 |
| 已下线 | `archived` | 编辑并保持下线、重新上线 | 停止公开，内容和历史保留 |

新建文章可以“保存草稿”进入 `draft`，也可以在通过发布校验后“保存并发布”直接进入 `published`。后续状态只允许 `draft → published`、`published → archived` 和 `archived → published`；不允许已发布或已下线文章回退为草稿，也不提供文章删除入口。

### 14.3 新建、编辑与发布校验

新建和编辑表单一次同时维护：

- 中文标题和英文标题；
- 中文正文和英文正文，正文允许输入 Markdown 文本；
- 使用中文逗号或英文逗号分隔的中英文关键词；
- 从十个固定分类中选择的分类；
- 有限数值的排序权重。

保存时去除标题、正文、分类和每个关键词首尾空白，过滤空关键词并去重。排序权重只要求是有效有限数值；当前业务不额外规定整数、正负范围或唯一性。

保存任何状态至少要求中英文标题、分类和有效排序权重。草稿允许中英文正文或关键词尚未完整；新建并发布、草稿发布、编辑已发布文章、已下线文章重新上线时，都必须同时具备非空中英文正文和至少一个关键词。任何发布门槛未满足时保持原状态，不得公开不完整内容。

编辑器提供中文和英文内容预览，用于核对当前选择语言的标题与正文；正文输入允许 Markdown 文本，但当前预览只承诺内容核对，不承诺最终客户端的 Markdown 排版效果。关闭、点击遮罩或按 Escape 前如存在未保存修改，必须先提示关闭会丢失这些修改；只有管理员确认放弃后才关闭。

### 14.4 发布、下线、重新上线与公开效果

从主列表发布草稿或重新上线已下线文章时，确认弹窗展示文章标题和“原状态 → 已发布”；从主列表下线已发布文章时，危险确认弹窗展示文章标题和“已发布 → 已下线”，并说明内容仍保留。这些确认弹窗只有取消和确认，不要求填写操作原因，也不存在额外审批人。

新建编辑器中的“保存并发布”、草稿编辑器中的“保存并发布”和已下线编辑器中的“重新上线”，在发布校验通过后由当前有权限的管理员直接执行，不再打开第二个确认弹窗。取消或执行失败保持原内容和原状态。

编辑已发布文章并保存时，文章继续保持 `published`，保存成功后新的双语标题、正文、关键词、分类或排序权重直接成为当前公开版本，不创建待审核草稿。管理员必须在保存前通过双语预览核对；需要先停止公开时，应先从列表下线文章再编辑。

学生只取得当前语言下状态为 `published` 的文章。下线只停止公开展示并更新时间，不删除文章内容、首次发布事实或审计历史；重新上线继续使用同一文章。管理端关键词和排序权重属于内容管理字段，不承诺进入学生端文章投影。

### 14.5 内容边界、并发、审计与失败

发布前必须确认文章适用于当前系统，与四份权威业务流程一致，不承诺尚不存在的能力，不把帮助文字当作权限或业务状态，也不包含密码、验证码、凭据、不必要的个人信息或其他敏感内容。帮助文章不能直接修改课程成员、打卡、审核、认证、免测、成绩、反馈、账号或系统模式事实；“维护期间操作”文章不等于系统模式发布的实时维护公告。

编辑保存必须基于打开编辑器时的最新更新时间；文章已经被其他操作更新时返回冲突，管理员重新打开最新内容后再决定是否修改，不能覆盖并发更新。目标不存在、字段不完整、状态转换非法、权限不足、重复提交或执行失败时保持原文章与原状态，不关闭错误表单或确认弹窗，也不得显示假成功。

每次成功创建、更新、发布、下线或重新上线都写入审计记录，保存操作者、时间、文章标识、变更前后内容或状态和结果；新建并直接发布作为一次创建记录并包含已发布状态。帮助中心不提供物理删除、定时发布、版本回滚、发布审批或发布通知流程，已经形成的文章历史和审计记录继续保留。

## 15. 审计日志

### 15.1 权限、范围与术语

正式审计日志属于上线范围，包含审计事件写入、列表查询、只读详情和服务器运行日志 ZIP。总管理员和具有“审计查询”权限的分管理员可以进入。

只有总管理员或具有“审计查询”权限的分管理员可以进入审计日志。查询始终受当前组织和管理员权限限制；操作人、对象、请求标识或其他筛选值不能扩大授权范围。学生和教师不访问系统级原始审计事件，即使教师是事件中的操作人或事件涉及本人教学班也不例外。

“审计日志”是查询页面，“审计事件”是其中一条不可变事实；其他章节中的“审计记录”或“审计历史”均指这些事件的保留集合。“服务器运行日志 ZIP”是独立的运行诊断归档，不是审计事件列表的 CSV、可编辑副本或当前可见行导出。

### 15.2 列表、筛选与分页

审计事件默认按发生时间从新到旧排列。列表至少展示发生时间、操作显示名称与稳定操作类型、实际结果、操作主体的角色快照与用户标识、对象类型与对象标识、请求标识和详情入口。无法识别的新操作、对象类型或结果按原值展示，不能误映射为已知操作或成功。

查询条件包括结果、请求标识、开始日期、结束日期、操作类型、对象类型、操作人和对象标识。所有已选条件共同作用于当前管理员有权查询的完整结果范围，并在分页前完成筛选；请求标识用于关联同一请求链路，操作人以事件保存的角色快照和用户标识为准，日期范围包含所选开始日和结束日。应用筛选、清空条件和刷新都从第一批结果重新开始，并且不改变任何业务事实或审计事件。

列表按批次向后查询，每批最多 50 条，不承诺预先知道总页数或总记录数；“当前结果数”只表示当前批次在现有条件下展示的数量。上一批和下一批按既定顺序展示，不得遗漏或重复审计事件。无结果表示当前授权范围和条件下没有匹配项，不表示历史被删除。

### 15.3 只读详情与安全元数据

详情至少展示事件标识、发生时间、操作人角色快照与用户标识、操作显示名称与稳定操作类型、对象类型与对象标识、实际结果、原因代码、请求标识和安全元数据。字段确实不存在时显示不可用，不得补造；结果为失败、错误、权限拒绝或业务驳回时必须保留实际结果，并在存在原因代码时如实展示，不能改写为成功。

安全元数据只能包含服务端允许用于排查的动作专属结构化字段。列表、详情和诊断归档均不得包含密码、验证码、Token、Secret、原始幂等键、原始 IP、原始设备指纹、User-Agent、完整个人资料、媒体内容、内部存储标识、签名下载地址、内部备注或原始业务快照；需要关联来源时只能使用经过批准的不可逆摘要或非敏感引用。

详情没有编辑、删除、补写、重放或重新执行入口。打开和关闭详情不新增业务操作，也不能借安全元数据直接修改原对象。

### 15.4 服务器运行日志 ZIP

授权管理员可以按当前已选的授权日期范围请求服务器运行日志 ZIP。归档由服务器异步汇总应用日志、健康摘要、请求关联和审计事件，并在服务端完成强制脱敏；归档范围只使用已选日期条件，不受当前表格可见行、当前批次或其他列表筛选条件影响，也不替代各业务页面的正式事实。

服务器正在生成时页面显示处理中；完成后只能通过服务器签发且经过安全校验的短时链接下载。仍在生成时管理员可以稍后检查同一任务；任务失败、取消、过期、链接无效或权限失效时不得下载，也不能在浏览器生成本地 ZIP、CSV 或其他替代文件。归档请求和下载仍受当前身份、组织范围、权限和服务端审计约束。

### 15.5 不可变性与失败处理

所有审计事件永久只读。任何管理员都不能编辑、补写、覆盖、删除或通过普通页面恢复审计事件；业务对象后来被修改、归档、匿名化或删除时，既有审计事件继续保留必要的非敏感历史关联，不能连带清除。

首次加载失败且没有有效结果时显示失败和重试入口；已经取得结果后刷新或翻页失败时保留原结果且不移动批次；详情加载失败时不生成替代详情；归档失败时不生成替代文件。查询、详情、分页或归档失败均必须显示真实失败，不得以缓存、合成数据或其他替代结果冒充成功。

## 16. 管理员与教师职责边界

| 业务事项 | 管理员 | 责任教师 |
|---|---|---|
| 当前课程 | 只读查看全部当前课程、学生人数和打卡情况 | 创建和管理本人课程 |
| 学期 | 创建、编辑即将开始学期并切换当前学期；旧当前学期自动归档 | 使用唯一当前学期 |
| 教学班 | 查看治理摘要 | 创建和管理本人教学班 |
| 分类目标 | 不代替教师设置 | 设置两类目标并保持合计 20 小时 |
| 学生入班 | 不审批 | 生成邀请，不审批正常加入 |
| 课程成员 | 账号安全操作不改变成员关系 | 移出或恢复本人教学班成员 |
| 官方名单 | 查看治理摘要 | 导入并核对本人教学班名单 |
| 打卡审核 | 不操作 | 追加有效或无效判断 |
| 耐力跑 | 不代审 | 确认真实用时和审核免测 |
| 校队/社团认证 | 不代审 | 审核并分配两类认可学时 |
| 学生成绩 | 维护 1000/800 米换算表，不确认真实用时，也不审批或修改单个最终成绩 | 确认真实用时、查看系统换算结果，填写和发布本人教学班最终成绩 |
| 用户反馈 | 统一受理、查询、更新状态、公开回复、关闭和重新跟进 | 不直接处理反馈单；按管理员协调核查本人教学班事实 |
| 系统模式 | 受控切换 | 遵守当前模式 |
| 帮助中心 | 管理面向学生的双语帮助文章 | 不创建、编辑、发布、下线或重新上线系统帮助文章 |
| 审计日志 | 按组织和权限查询事件、查看脱敏详情并请求运行日志 ZIP | 不访问系统级原始事件或运行日志 ZIP |

## 17. 明确不属于管理员端的能力

- 抹除全部业务数据或一键清空系统；
- 修改、补写或删除审计事件；
- 使用固定口令执行不可逆删除；
- 直接修改底层业务数据；
- 查看教师已经修改后的个人密码；
- 分管理员创建或授权其他管理员；
- 创建、编辑、关闭、恢复或删除课程；
- 代替教师审核打卡、确认耐力跑、发布成绩或审批免测认证；
- 改写学生正式运动时长或媒体事实；
- 使用“增加 60 分钟”；
- 管理员直接修改学生最终成绩或审批教师填写的最终成绩；
- 删除已发布成绩、打卡审核、课程成员或官方名单历史；
- 开启定位采集、轨迹或地图查看；
- 在证据不足时转移教师课程、合并身份或自动修复名单冲突。

## 18. 管理员端主流程

1. 初始总管理员首次登录后先修改本人临时密码，再进入其他管理员业务。
2. 总管理员建立必要的分管理员，并从系统支持的管理动作中为其自定义组合权限；分管理员首次登录后也先修改本人临时密码。
3. 管理员创建和编辑 `UPCOMING` 学期；目标学期到达开始日期后确认切换，并只读查看责任教师创建的当前全部课程、学生人数和打卡汇总。
4. 管理员先校验 UTF-8 CSV 和强初始密码，再批量建立教师账号；学生账户仅允许搜索、筛选和查看详情。
5. 教师首次登录后必须先设置个人密码，再进入其他教师业务。
6. 管理员统一受理学生反馈，按编号、提交人、分类、内容和状态查询；每次更新状态时追加公开回复和审计记录，必要时另行协调责任教师核查课程事实。
7. 具有全局规则权限的管理员维护四套 1000/800 米换算表；系统据教师确认的真实用时生成耐力跑换算结果，单个学生最终成绩仍由责任教师填写和发布。
8. 管理员受控切换正常和维护模式。
9. 管理员创建、编辑、发布、下线和重新上线面向学生的双语帮助文章。
10. 授权管理员查询审计事件、查看脱敏详情，并按授权日期范围请求服务器运行日志 ZIP；不能修改、补写或删除审计事件。
11. 目标学期已经到达开始日期后，管理员确认切换，系统自动归档旧当前学期；归档历史只读保留。
