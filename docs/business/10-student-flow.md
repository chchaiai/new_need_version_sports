# BNBU Sports 学生端业务流程（Android / Web）

> **文档版本**：v8.0
> **更新日期**：2026-09-04
> **文档范围**：本文只描述学生可见的业务规则、操作条件、状态变化和异常处理，不记录技术实现细节。
> **业务决策说明**：本文记录用户确认的目标业务规则，不表示当前产品已经全部实现。
> **本轮决策**：用户已确认教师辅助优先方案；本版为目标业务基线，尚未完成客户端、Backend、数据库或 Contract 迁移。

## 1. 学生端定位

学生通过有效邀请注册入班、完成运动、提交凭证、查看本人原始体测数据和打卡进度，并按教师要求一次补证。平台统一规则，学生不投票、不协商课程公式，也不进入多级申诉或自助延期审批链；一般问题仍可通过既有服务反馈提交事实说明。

当前学生端仅开发 Android 与 Web，两端遵守同一业务基线。学生只查看本人数据，不展示课程最终分数、耐力跑换算分、等级或排名。正式体测和课程成绩由学校指定的本人查询渠道反馈；本规则不意味着该外部渠道已经建成。

## 2. 全局业务规则

| 业务事项 | 统一规则 |
|---|---|
| 学生身份与状态 | 已验证学校邮箱；状态仍只有 ACTIVE（已进班）/PENDING（已退班），名单冲突与审核待办不新增账号状态 |
| 数据范围 | 仅本人身份、本人课程与原有历史记录的授权范围 |
| 同学期课程 | 同一时间一个有效体育教学班；正常邀请入班不审批 |
| 日期与周 | 运动开始时由服务器固定上海业务日期；周一至周日，结束、上传或补证不改归属 |
| 运动时长 | 服务器累计会话 ACTIVE 区间，排除 PAUSED；手机显示计时不直接入账 |
| 默认课程门槛 | 满 30 分钟开始计入；教师开课前只能选 30/45/60 分钟 |
| 单次可计分钟 | 未达门槛为 0；达门槛后按完整实际分钟计，单次最多 60 分钟 |
| 每日与每周 | 允许同日独立新运动；每日最多一条计入，默认每周三条、不同日期；教师开课前可选 2/3/4 条 |
| 总目标 | 两类目标合计 1,200 分钟，分别封顶；有效认证仍参与分类完成量 |
| 达到上限 | 日、周或学期上限只限制考核计入，不单独禁止继续记录运动 |
| 提交与审核 | 系统校验后待 AI；正常自动有效，异常待教师；技术故障不等于无效 |
| 补证 | 同一记录最多一次；教师选择 24/72 小时，原运动事实不变 |
| 计入选择 | 系统按总进度最大原则选择，规则见总流程第 11.3 节；学生、教师均不手工分配名额 |
| 公开信息 | 原始体测、实际计时、可计/计入分钟、剩余目标、审核状态、公开原因和期限 |
| 隐藏信息 | 最终分数、换算分、等级、排名及通过接口、通知、导出泄露这些信息的路径 |
| 历史与审计 | 事实和判断只追加留痕；学生不访问系统原始审计或运行日志 ZIP |
| 通知 | 仅站内通知；已读不改变结果，不设置短信、邮件或设备 Push 作为完成条件 |
| 位置与正式入口 | 不采集定位轨迹；不提供模拟扫码、Fake Success 或失败回退 Mock |
| 版本策略 | 辅助检查失败不单独阻断 App；已缓存的强制升级不得被清除或绕过 |

## 3. 主要业务入口

| 入口 | 学生可完成的事项 |
|---|---|
| 首页 | 查看课程规则、本人剩余目标和需补证事项 |

| 我的 | 邮箱、偏好、隐私、帮助、反馈和本人账号 |

## 4. 启动与系统模式

学生端启动后：

1. 读取本人已保存的语言、主题和必要偏好；
2. 检查当前版本策略；
3. 取得当前系统模式；
4. 有有效登录状态时恢复本人身份；
5. 登录状态失效时返回登录或课程邀请入口；
6. 按当前系统模式决定可进入的页面和可执行的操作。

版本策略检查是启动辅助检查。单个辅助接口本次故障本身不能使整个 App 不可用；但本机已经缓存强制升级要求时，本次检查失败不得清除、降低或绕过该要求。客户端只有取得新的权威版本策略结果后，才能按新结果更新已保存的要求。

| 系统模式 | 枚举 | 学生端行为 |
|---|---|---|
| 正常模式 | `NORMAL` | 按本人身份、课程成员关系、资源归属和业务状态完成已开放业务 |
| 维护模式 | `MAINTENANCE` | 暂停普通业务访问，展示管理员发布的中英文维护公告和预计恢复时间；对已有补证提示计时暂停及剩余时间，不开放提交 |

进入维护模式前尚未完成提交的内容不会自动成为正式业务记录，也不得被显示为已提交；是否存在本地草稿及其保留方式仍按对应页面既有草稿规则处理，系统模式本身不作额外承诺。预计恢复时间只用于告知，不会让客户端自行解除维护限制；授权管理员明确切换到正常模式后，学生端重新取得系统模式和最新业务状态，再开放相应入口。

进入维护模式时，学生补证计时与自动逾期判定暂停，页面展示维护公告、计时暂停和剩余时间；系统正式恢复 NORMAL 后继续剩余计时，不重置完整窗口、不扣除维护时段。非维护平台故障继续按第 7.7 节确认影响并调整期限，不由学生改本机时间决定。

学生不能通过修改本机时间、缓存、旧页面状态或重复请求绕过系统模式限制。模式切换不删除或改写学生已有的课程成员、打卡、审核、认证、免测、成绩、反馈或账号事实。

## 5. 登录与账号

### 5.1 已有学生登录

已有学生使用已验证的学校邮箱和一次性验证码登录。

当前学生端不使用手机号或短信登录，也不设置传统登录密码。连续输入错误或频繁申请验证码时，系统可以暂时限制继续尝试。

### 5.2 新学生通过课程邀请建立账号

1. 学生扫码或输入邀请码；
2. 查看教学班、课程、教师、学期和邀请状态；
3. 填写姓名、学号、性别和年级；
4. 确认加入；
5. 系统检查当前学期是否已经存在有效体育教学班；
6. 条件满足时建立学生身份和有效课程成员关系；
7. 学生绑定并验证学校邮箱；
8. 完成后进入课程和首页。

正常加入不需要教师或管理员审批。

如果学生在当前学期已经存在有效体育教学班，新的加入必须拒绝。原责任教师将学生移出原教学班后，只要学生当前没有其他有效体育教学班，就可以通过新邀请加入其他教学班。

### 5.3 邮箱绑定与换绑

- 首次绑定时，新邮箱必须完成验证码确认；
- 更换已验证邮箱时，当前邮箱和新邮箱都需要验证；
- 无法访问当前邮箱时，学生联系学校体育部门或管理员完成身份核验；
- 仅修改页面显示不能改变已验证邮箱。

### 5.4 学生状态

学生状态只描述当前课程成员关系，不描述邮箱绑定流程、登录会话或身份恢复申请：

- `ACTIVE`：学生已绑定并验证学校邮箱，当前处于有效体育教学班中，页面显示“已进班”；
- `PENDING`：学生已绑定并验证学校邮箱，但已被责任教师移出且当前没有有效体育教学班，页面显示“已退班”。

学生正常加入或被原责任教师恢复到教学班后，状态从 `PENDING` 变为 `ACTIVE`；责任教师将学生移出当前教学班后，状态从 `ACTIVE` 变为 `PENDING`。首次邮箱绑定完成前使用的临时认证状态不属于学生状态；身份恢复申请也是独立事项，不能把学生状态改成 `RECOVERY_REQUIRED`、`DISABLED` 或其他枚举。

学生首页的体育学时进度标签必须受当前学生状态约束：只有 `ACTIVE` 学生可以显示“进行中”；`PENDING` 学生显示“已退班”，即使本地缓存或旧进度快照仍带有进行中字段，也不得继续显示“进行中”。`ACTIVE` 学生已经达标时可以显示“已达标”。Android 与 Web 遵守同一显示语义。

### 5.5 退出登录

退出登录后，当前设备的登录状态失效，并清除本机保存的身份凭据。

### 5.6 注销本人账号

账号注销需要再次验证本人身份。

1. 学生查看注销影响；
2. 使用当前已验证邮箱接收验证码；
3. 输入验证码并确认注销；
4. 系统检查是否存在进行中的运动或其他阻塞事项；
5. 条件满足时删除本人登录账号、密码凭据、现有登录会话、验证码/验证挑战、学校邮箱以及当前学生资料中的姓名、学号等账号相关数据；
6. 所有设备退出登录，原账号不能继续登录或被静默恢复；
7. 返回登录页。

注销不删除必须保留的课程关系、运动记录、正式媒体、审核、成绩和审计历史。这些保留事实只能关联一个不具登录能力且不含当前账号资料的内部历史主体标识，不能借此恢复已删除账号。

### 5.7 管理员只读查看边界

管理员可以在“用户与账号”页面搜索、筛选并查看学生必要资料和当前学生状态，但不能在该页面修改学生姓名、学号、性别、年级、学院、专业、班级、邮箱、角色、学生状态、课程关系或登录状态。学生列表和详情只显示 `ACTIVE` 或 `PENDING`；待核验身份恢复申请是独立事项，不作为学生状态，也不代表管理员可在学生详情直接批准、驳回、改绑或恢复账号。

## 6. 课程加入与查看

### 6.1 加入课程

学生可以扫描课程二维码，也可以手动输入邀请码。两种方式遵守相同的预览、确认、同学期唯一教学班和直接入班规则。

二维码和手动邀请码使用同一规则：默认有效 30 分钟，责任教师可在 5—120 分钟内设置有效期限，并可主动撤销。自然到期后不能发起新的入班流程；仅自然到期前已由服务器登记的同一次注册流程可在到期后再完成 10 分钟，宽限仅一次、不得刷新续期。邀请撤销、入班关闭、课程关闭或学期失效立即终止宽限；最终入班仍检查有效身份和同学期唯一教学班。二维码过期不影响已加入成员。

成功加入后，学生立即成为该教学班的有效成员，不进入等待教师审批状态。

初版班级必须由责任教师创建并生成邀请码。学生只能通过有效邀请码加入，不能自行创建班级、从未授权的班级目录自由选择班级或把本地选择当作正式成员关系。

正式产品不提供“模拟扫码成功”、`Fake Success` 或合成/Mock 学生工作区入口。开发或测试入口即使展示加入后的页面，也不能建立课程成员关系，不能写入正式业务事实。

### 6.2 课程列表与详情

学生只能查看本人课程成员关系范围内的信息，包括：

- 教师自定义的课程名称；课程代码和教学班号不属于学生端业务信息；
- 当前学期和责任教师；
- 允许打卡的日期或时间范围；
- 课程相关运动目标；
- 其他运动目标；
- 本人的课程成员状态；
- 本人的打卡、认证认可分钟、原始体测和剩余目标，不含分数、等级或排名。

学生课程页只展示当前有效课程关系，不使用“已结束”课程状态。管理端目录的 `UPCOMING` 或 `ACTIVE` 及其成员、打卡、目标和时长汇总只用于管理员了解当前课程运行，不开放单条打卡或媒体处理，也不能改变学生的课程成员关系、入班资格或打卡结果。

管理员只有在目标 `UPCOMING` 学期已到开始日期且旧学期课程完成收尾结算后才能切换；成功后旧学期归档，新学期成为唯一当前学期。后续新运动只发生在新的当前学期；旧事实仅允许有权限教师作受控纠错并追加新版结果，不覆盖历史。

学校官方名单是教学管理快照，不等同于学生已经加入课程。名单内“注册核对完成”要求邮箱已验证、已加入该班且学号/姓名匹配；信息冲突交教师处理，不自动合并身份、退班或拒绝已经符合邀请条件的学生。注册完成、体测录入和打卡达标分别显示。

### 6.3 课程关闭后的既有业务

课程关闭只阻止新的业务起点：不再建立新课程成员关系、新运动会话或新的免测/认证申请，不重新开放邀请或补练。关闭前已由服务器合法建立或受理的业务继续按原规则完成，包括已有会话的后续处理与结束、该次运动首次材料提交、已锁定同批材料续传、异常审核与一次补证、已受理名单/OCR 和免测/认证处理，以及收尾结算。关闭本身不能截断这些既有业务链、缩短其原有效期限，或把记录自动判无效；教师为关闭前合法记录退回一次补证，是原业务的后续处理，不是新运动。

关闭后形成的上述后续受理、审核、补证和结算事实必须关联关闭前的合法对象，保留服务器确认时间和历史；本地草稿、未确认的运动或尚未建立的成员关系不因此变为合法事实。原材料期限、课程规则、权限、维护暂停和一次补证限制继续适用，课程关闭不自动增加补证机会或无限延长期限。邀请撤销/关闭立即终止尚未完成的入班宽限；课程关闭不等同于结算或学期归档，结算及归档仍须先完成合法待办。

学生不能因课程从当前开放列表消失而失去本人关闭前合法记录的材料提交、补证或结果查看入口；入口仅服务该旧业务链，不能用于新运动或新申请。维护期间提交仍暂停，恢复正常后按剩余时间和原资格继续。成员移出或学期归档是独立约束，不能仅凭本节推定全部首次材料提交都继续放行。

### 6.4 学生不可执行的课程动作

- 不能自行退出课程；
- 不能删除课程成员历史；
- 不能自行转班；
- 不能恢复已被教师移出的成员关系；
- 本版责任教师完成本学期教学，不设置学期中删除责任教师或删除后接管课程；完成学期后的账号治理不删除本人的课程关系和业务历史，也不转移课程责任教师；
- 不能在已经存在有效体育教学班时同时加入第二个教学班；
- 不能通过修改本地课程信息制造已加入、已退课或已转班状态。

## 7. 运动打卡与一次补证

### 7.1 开始前条件

账号和身份有效、邮箱已验证、当前学期未归档、课程未关闭且有唯一有效教学班、处于普通打卡时间或责任教师为本人开放的收尾补练窗口、没有另一条 ACTIVE/PAUSED 会话，且当前系统模式允许业务。

达到日、周或学期计入上限后仍可运动并留下记录；页面明确上限和本次可能不计入的原因，不能将其伪装为额外考核学时。常规截止后的七天收尾期不对全体学生自动开放新运动，只有获准补练的学生可以新建会话；结算或归档后不新建补练。

### 7.2 运动状态与时间事实

会话仍为 ACTIVE ↔ PAUSED → COMPLETED；ACTIVE 或 PAUSED 都可结束，结束后不可恢复。服务器累计 ACTIVE 区间并排除 PAUSED，跨后台、重启或更改设备时间不能改写服务器认定的时长。该计时不能单独证明全过程真实运动，凭证仍需检查；不得通过“增加 60 分钟”或截图手工补造计时。

业务日期在服务器受理开始时固定为上海日期，并据此确定周。新运动必须是独立、无重叠会话；补证、上传重试和跨午夜均不新建次数或改写原归属。

### 7.3 可计分钟与课程规则

课程默认门槛 30 分钟，教师只能在开课发布前选择 30/45/60 分钟；周上限默认三条，可选 2/3/4 条。单次上限固定 60 分钟，两类目标合计 1,200 分钟。已发布模板和分类目标锁定，既有记录不追溯套用新版本。

未达到当次门槛，可计分钟为 0；达到后按完整实际分钟向下取整，最多 60 分钟。例如默认门槛下 29 分 59 秒可计 0、35 分钟可计 35、80 分钟可计 60。页面仍保留准确计时事实，不把可计分钟冒充实际时长。可计分钟还须经有效审核、日/周限制及分类封顶后才成为实际计入分钟。

### 7.4 分类与说明

选择课程相关运动或其他运动并填写去除首尾空格后 1—200 字说明。类别决定目标归属；游泳前后凭证要求属于运动项目要求，不新增第三类学时目标。学生不能改变课程模板、公式和目标，不能将一类超额转入另一类。提交后不能改运动日期、时长或类别。

### 7.5 送审材料版本

每版送审材料最多 6 张 JPEG/PNG 照片和 1 段 MP4 视频，至少一项有效媒体；单张最大 10 MB，视频 1—15 秒且含音轨、最大 100 MB，每版合计最大 250 MB。正常流程最多首次提交与一次补证两个材料版本；首次及补证包分别校验，不将版本当成新的运动记录或新次数。补证可引用原素材并追加本次运动的相关材料，原版媒体永久只读保留，不能物理删除或覆盖。6 图＋1 视频限制当前送审包而非两版历史的合计；两版存储不得重复计入同一素材。该上限不套用到免测/认证申请，后者仍按同一申请累计最多 3 张图片执行。

上传前可预览并删除尚未上传的本地素材；上传开始或正式受理后不能删除正式材料。客户端预检与服务器权威校验都必须执行，文件不合格不得形成假成功。运动截图只能作为辅助材料，不能单独制造会话、补填时长或自动证明运动真实发生。

### 7.6 游泳与延迟提交

游泳每版有效送审包必须保留本次运动前、运动后照片各一张，照片总计 2—6 张；视频可选，最多一段，沿用上述大小与格式要求。系统明确标记前后阶段并关联同一会话；不要求水中、更衣室或其他禁止拍摄区域取证，不强制露脸。缺少运动前证据不能用事后新拍照片冒充补齐。

游泳结束后 15 分钟内，提交必须由服务器受理并锁定材料；已受理的同批材料在受理后 30 分钟内可续传，续传不能换一批文件。完全离线时可在结束后 24 小时内提交延迟说明及已有会话、材料，进入教师异常队列，不能只凭本地时间、图片时间或截图自动通过。延迟提交不是另开一次补证，也不能补造运动会话或改变原业务日期。普通运动不自动套用游泳的 15 分钟窗口；仍须在课程提交与收尾期限内完成。

对游泳记录的 15 分钟初次提交限制不重新套用到教师已开放的补证，补证按退回时的 24/72 小时截止执行，并保留原运动前后证据。续传只延续服务器已锁定的同批文件；未完成传输不能进入有效审核，个人原因逾期按延迟异常规则处理，平台故障保留技术状态及受影响时段，不自动判违规。服务器结束时间仍是正式结束事实，离线说明不能倒改结束或增加运动时长。

课程关闭不额外截短关闭前合法会话已经适用的首次提交或同批续传窗口，也不把该次首次提交误当成新运动；材料仍须符合原游泳规则及已有期限，不能借关闭绕过材料要求。


### 7.7 AI 初审、教师复核与补证

用户本轮明确不新增公开分类。补证后判无效的终结规则，不等于新增“仍有怀疑即可判无效”的标准；六类均不适用的边界仍见[总流程待决边界](00-overview.md#04-待决边界)，不得自创分类或把未证实事实写成已证实违规。

提交成功只代表记录和首版材料被受理，不代表立即有效或计入。处理分为：待 AI 检查、待教师复核、待补证、有效、无效；AI 故障另显示技术处理中，不映射成学生无效。正常内容由 AI 检查通过后自动有效；缺少关键材料、内容不符、疑似重复、信息矛盾或无法判断进入教师异常队列。

教师审核只有三个动作：通过、退回补证、判为无效。退回补证后原记录处于待补证，不是立即无效；教师判为无效或系统补证逾期会形成记录无效状态，不改变学生账户状态。这里的“补证”是补充原次运动材料，不是重新运动或新建一次打卡。

教师退回或判无效时必须选择一个适用的固定公开分类；学生只查看本人收到的分类与公开说明，不能选择或修改审核原因：

| 固定公开分类 | 英文名称 | 适用教师动作 |
|---|---|---|
| 材料不清晰 | Unclear evidence | 退回补证、判为无效 |
| 必需材料缺失（含要求的前后照） | Missing required evidence | 退回补证、判为无效 |
| 材料与本次运动不符 | Evidence does not match this session | 退回补证、判为无效 |
| 材料信息矛盾 | Inconsistent evidence | 退回补证、判为无效 |
| 材料真实性待核实 | Evidence authenticity requires clarification | 仅退回补证 |
| 经核实存在重复使用或冒用材料 | Confirmed reuse or misuse of evidence | 仅判为无效 |

退回补证还必须满足尚未使用一次补证机会，并且能够补充原次运动的材料；不能要求事后补拍照片冒充运动前证据，也不能要求重新运动来补造原记录。“材料真实性待核实”只能用于退回，疑似重复或冒用不等于已证实违规；补证后须依据复核事实通过或选择适用的判无效分类，不能仅因仍有怀疑就选“经核实存在重复使用或冒用材料”。同一记录补证时合法引用原素材、同批续传及重复请求不属于违规重复使用。不强制露脸、不采集定位的既有边界不变。

固定分类和系统原因均维护中文、英文名称，按客户端当前语言展示；教师补充说明按输入原文公开，不要求教师填写双语，也不默认自动翻译。学生在本人的补证页、记录详情和站内通知中看到相同的公开分类及已填写的公开补充说明。不设置隐藏审核备注，不是“保存内部备注但不给学生看”；公开说明不能写入他人隐私或敏感信息。

每条记录正常流程只允许退回补证一次。教师退回时选择默认 24 小时或特殊 72 小时总窗口，由服务器确认退回成功时启动学生补证计时；72 小时不是额外增加 72 小时。不设置学生自助延期申请队列、多级审批或滚动延长。

系统进入维护模式时，立即暂停尚未结束的学生补证倒计时和自动逾期判定，保留已经消耗的时间与剩余时间；维护期间不消耗剩余时间，也不能仅因原截止到达就判无效。只有服务器确认系统恢复 NORMAL 后，才按剩余时间继续计时，不重新发放完整的 24/72 小时，也不补扣维护期间的时间。多次维护分别记录、按实际暂停区间去重计算；恢复后的截止重新计算并公开给学生，维护期间显示“计时已暂停”和剩余时间，预计恢复时间不是实际恢复时间或最终补证截止。

非维护的平台故障确实影响提交时，仍按已确认的受影响记录与不可用时段调整期限，保留原截止、调整原因与新截止，同一时段不重复补偿；个人离线不冒充平台故障。自动逾期必须先核对当前系统模式、暂停/恢复记录、已确认的故障调整和正式受理事实，不能先按失效的旧截止判无效，再把维护顺延作为新一轮补证。维护开始前已经真实逾期终结的记录，不因进入维护或恢复正常而重新取得补证机会。

教师退回后，记录进入待补证。最终补证截止时间以原窗口、实际维护暂停/恢复记录及已确认的故障调整为准；非维护状态下，扣除不应计时的时段后补证剩余时间耗尽，记录仍待补证且服务器未在最终截止前正式受理符合提交条件的补证包，系统自动追加无效结果并通知学生，不要求教师再次点击。公开原因为“补证逾期 / Supplementary evidence deadline missed”，属于系统生成的学生可见结果原因，不进入教师原因下拉选项，也不是第四个教师动作。“无效”是该条记录的结果状态，不是学生账户状态。

补证逾期无效后，该原记录不能再次补证，不再开放补证入口，也不接受学生针对该记录再次上传补证材料；原记录、已提交材料和判断历史继续保留。不能以再次退回或纠错重置补证次数；此限制不禁止符合课程条件的独立新运动，也不允许借新记录重复上传原材料领取学时。

正常补证已按时受理后，不再因为教师尚未复核而自动判逾期；复核等待不占用学生补证时间。正式受理只表示补证包符合提交受理条件，不表示教师已经审核通过；开始上传、本地保存或教师尚未复核都不能代替服务器的受理事实。

学生在原记录补证页面核对公开原因、最终截止或维护暂停提示和材料，提交一次补证包。补证正式受理后学生计时结束，等待教师新一轮复核，不由 AI 自动覆盖教师决定。正常结果不需要学生逐条申请教师批准。

补证正式受理后，教师只能执行通过或判为无效，不再次退回补证。若补证后仍被判为无效，直接结束该记录的正常审核流程，不再提供补证入口，不再接受该记录的后续补证材料；教师必须选择适用的固定公开原因，可再写一句公开补充说明，不能用再次退回代替最终判断。补证后判无效和补证逾期无效都不产生新的补证机会。

有权限教师仍可依据已存在事实追加误判更正，保留原系统或人工判断及通知记录；纠错不重置补证次数，不重新开放补证入口，不改写原始运动、材料或审核历史。学生说明在原记录内处理，不建立额外多级申诉、多人会签或学生延期审批队列。

异常记录正式进入需要教师动作的待办时，启动本轮两个学校工作日的教师 SLA（异常处理时限）。服务器确认教师执行通过、判为无效或退回补证成功时，本轮教师 SLA 结束；只打开详情、刷新、重复请求或执行失败不结束或重置计时。等待 AI、纯技术处理中和等待学生补证不计入教师当前处理轮次。

教师退回成功后，本轮教师 SLA 已结束，学生的 24/72 小时补证计时器开始。学生补证被服务器正式受理时，学生计时器结束，记录重新进入教师待办，启动全新的两个学校工作日 SLA，不沿用上一轮已消耗时间或剩余时间。教师随后通过或判为无效时，新一轮 SLA 结束；学生未补证而真实逾期的记录由系统终结，不因此生成一轮教师待办。

维护期间暂停正在进行的教师 SLA，恢复 NORMAL 后继续本轮剩余处理时间，不重开一轮；学生补证计时也按维护暂停规则执行。两个工作日采用学校统一工作日日历，不由教师自定义，也不等同于固定 48 小时。教师超时只触发教师提醒与管理汇总，不自动判学生无效；通知是否已读不决定任一计时器的起止。

### 7.8 记录无效后继续运动

无效记录不占最终计入名额，但原记录与材料保留。学生可在同一业务日期重新实际运动并形成新记录，仍受唯一进行中会话、课程开放和每日最多一条计入限制；不能把同一次运动拆开或仅重复上传原材料领取新学时。原记录后来恢复有效时系统重新选择，不能与同日记录重复计入。

## 8. 本人数据与运动进度

### 8.1 本人可见内容

展示体测项目、真实用时、测试日期或免测状态；每次运动的计时、可计分钟、实际计入分钟、审核结果和未计入原因；两类目标、当前有效认证、完成量、剩余量及期限。

课程最终分数、耐力跑换算分、等级和排名均不向学生展示；接口、通知、导出及旧缓存也不能绕过此边界。已有成绩事实不删除，学校指定渠道承接正式反馈；本 App 不新建学生成绩查询入口。课程进度可显示百分比，但不命名为进度分数或成绩。

### 8.2 计入选择与分类统计

系统在有效候选记录中，联合考虑每日最多一条、每周最多课程规定条数、单次上限和两类目标上限，选择使该学生总有效进度最高的合规记录组合。只在当前有效且审核完成的记录中选择；同总量时优先保留原计入组合，其次按运动开始时间、稳定记录标识排序。不能先取每天或每周最早记录后再封顶，也不能用单类贪心选择代替完整约束。

有效认证认可分钟按既有分类规则参与计算，不消耗运动记录的日/周名额；无效或撤销认证不贡献分钟。每类完成量为选中 Record 可计分钟与当前有效认证分钟之和、最多本类目标；两类相加最多 1,200 分钟。记录有效不等于全部可计分钟均已计入；系统分别展示可计分钟、实际计入分钟及未计入原因。补证与判定改变只重算计入投影，不改写会话时长、原规则、材料或审核历史。

在课程规则、目标和认证额度不变时，仅增加有效候选或补证通过不得降低总有效进度；纠正为无效或撤销认证可以减少进度，但必须说明原因。当前有效但因上限未计入的记录不能显示为无效。补证沿用原运动日期和周，不占补证当天或当周名额。课程级汇总先完成每名学生的选择和分类封顶，再汇总，不能全班统一封顶。

课程完成率为 min(总有效分钟 / 1,200, 100%)；展示可四舍五入为整数百分比，判断用原始分钟值。待 AI、待教师、待补证与技术处理中均不计已完成，也不显示为无效。达到目标后仍可继续记录个人运动，考核进度不超过目标。

### 8.3 期末收尾

开课即公布常规打卡截止、其后七天收尾期和考核结算安排。常规截止前 14 天收到剩余目标及未处理事项提醒。收尾期只有教师明确授权的本人补练窗口允许新运动；按真实日期记录，不倒填旧周。

结算前须处理完补证及其复核；仍未提交且期限有效（含故障顺延）的记录必须等待截止，已按时提交并完成审核的记录无需空等原截止。系统或教师未处理不能批量算学生无效。学期归档安排在收尾与结算之后。归档后不新增运动或常规补证轮次，只允许教师按专项纠错流程追加旧事实更正；历史报告保留并形成更正版。学生仅查看与本人相关的结果和公开原因。

## 9. 耐力跑、成绩换算、免测与校队/社团认证

### 9.1 耐力跑真实用时

女性展示 800 米真实用时，男性展示 1000 米真实用时。真实用时由责任教师根据正式测试结果确认。

### 9.2 耐力跑换算与显示边界

责任教师确认真实用时后，系统按学生性别、年级组和项目匹配唯一换算表；教师内部可查看换算分和等级，学生仅查看原始项目、用时、日期或免测状态。没有唯一匹配规则时内部结果不可用，不猜分。

换算分不增加打卡分钟、不自动成为最终成绩；换算表变更不追溯覆盖历史。学生接口、通知与导出不返回换算分、等级或最终分数。体测 OCR 只产生待教师确认的草稿，未确认内容不显示为学生正式测试数据。

### 9.3 耐力跑免测

学生提交耐力跑免测申请和证明材料，由责任教师审核。证明材料只接受 JPEG、PNG 或 WebP 图片，不接受 PDF、视频或其他文件格式；同一份申请的首次提交和全部补充提交合计最多 3 张，单张最大 10 MB。学生可以拍照或从相册选择符合规则的图片，并在申请详情中查看已上传图片的缩略图。

批准后，学生记录界面的耐力跑位置显示免测，不显示真实用时，也不按普通用时换算表生成分数或等级；免测不增加打卡总时长、不改变 20 小时进度参考，也不会自动改写教师已发布的最终成绩。

### 9.4 校队和社团认证

学生提交校队或社团证明材料，由责任教师审核。证明材料沿用耐力跑免测的图片规则，只接受 JPEG、PNG 或 WebP；同一份申请的首次提交和全部补充提交合计最多 3 张，单张最大 10 MB，并在申请详情中展示缩略图。

批准后，责任教师自定义认可总时长，并按实际情况分配到：

- 课程相关运动认可学时；
- 其他运动认可学时。

课程相关运动和其他运动都可以获得认可学时，任一类可以为 0，不固定只抵扣某一类。每类认可学时不能超过对应分类目标，两类合计不能超过 20 小时。学生仍需完成没有被认可的剩余分类学时。

认证被撤销后，相应认可学时取消，学生需要补足差额。历史继续保留。

## 10. 站内结果、偏好、帮助与反馈

### 10.1 站内结果

学生在对应页面查看课程成员、打卡审核、免测、认证、原始耐力跑数据和本人结算进度，不查看分数、等级或排名。

成员关系、打卡审核与补证期限、免测、认证、原始耐力跑数据、反馈处理以及系统维护或恢复等面向本人的正式结果变化进入站内通知中心；不发送最终分数、换算分、等级或排名。系统不发送短信、邮件或 Android 系统 Push；通知是否已读不改变业务结果，业务是否完成仍以对应页面显示的正式状态为准。

打卡审核通知使用第 7.7 节同一公开分类和已填写的公开补充说明，固定分类按当前语言显示，补充说明保留原文。补证逾期通知明确是系统处理、原因为“补证逾期”、记录已无效且不能再次补证；补证后教师判无效的通知也明确不再提供补证。维护暂停与恢复提示使用服务器确认的状态和剩余时间，不伪造教师备注或重新开放已终结记录的补证入口。

### 10.2 偏好

学生可以调整本人支持的语言、主题和界面偏好。偏好不能改变身份、课程关系、审核结果或成绩。

### 10.3 帮助中心

学生可以从本人设置进入帮助中心，按当前客户端语言取得管理员已经发布的帮助文章，并按客户端提供的搜索和分类方式查看标题、正文及分类。每次只返回当前语言投影，不同时暴露中英文编辑源；切换客户端语言后重新取得对应语言内容。学生不能查看草稿、已下线文章、管理关键词、排序权重或审计信息。

只有状态为已发布 `published` 的文章属于当前正式帮助文章。草稿 `draft` 从未公开；文章变为已下线 `archived` 后停止公开，但不会删除管理端历史。客户端因加载失败而展示最近缓存时必须明确标识为缓存内容，不能把缓存中的旧文章冒充为当前仍已发布；加载恢复后重新以服务端当前结果为准。

帮助文章只用于解释既有业务规则，不能授予权限、改变课程成员、打卡、审核、认证、免测、成绩、反馈或账号事实。文章内容与对应业务页面冲突时，以权威业务流程和对应页面的正式状态为准。

“维护期间操作”分类的帮助文章是普通自助说明，不是当前维护公告。系统进入维护模式后，实时维护公告和预计恢复时间由系统模式流程展示，学生不能把帮助文章中的日期或说明当作当前系统状态。

### 10.4 服务反馈

Android 与网页学生端统一提交问题类型（功能异常、功能建议、无障碍问题、隐私问题、其他）和问题描述。系统把反馈与已登录学生身份关联，生成反馈编号、提交时间和初始状态“待受理”；管理端按同一分类与问题内容展示，并补充提交人姓名、学号和当前学校邮箱。客户端平台、版本、附件、优先级、指定处理人和内部备注不属于当前管理界面的业务字段。

负责处理反馈的分管理员由总管理员使用独立账号、姓名、有效且唯一的学校邮箱、可选所属部门、初始密码和至少一项业务权限建立，创建后默认启用。学生问题反馈是 8 项可分配权限之一；系统概览自动可见，分管理员设置不能下放。总管理员可以编辑权限、停用、重新启用或删除分管理员，但删除前必须先移交职责，且不会清除已经完成的学生反馈或审计历史。该治理方式不改变学生提交和查看反馈的流程。

学生提交反馈后，反馈统一进入管理员队列。学生可以查看本人反馈的当前状态和管理员公开回复，但不能选择处理状态、代替管理员回复、删除处理记录或指定处理人。

反馈状态依次表达当前处理阶段，但不是固定的单向审批链：待受理表示尚未开始处理，受理中表示管理员正在跟进，待技术团队处理表示需要技术排查，处理完成表示当前已经给出处理结果，已关闭表示本轮反馈结束。管理员首次处理待受理反馈时默认进入受理中；以后每次保存状态都必须同时新增一条学生可见回复。处理完成或已关闭后确需继续跟进时，管理员可以重新设为受理中或待技术团队处理，并新增说明，已有记录继续保留。

课程问题需要教学事实时，由管理员另行协调责任教师核查；当前反馈界面不建立面向教师的转交或指派关系，反馈状态和公开回复仍由管理员维护。反馈本身不能直接修改打卡、成绩、申请、账户状态或课程关系，学生仍须以对应业务页面的正式结果为准。

## 11. 异常与隐私

- 重复点击不能产生重复课程关系、打卡或申请；
- 数据已被其他操作更新时，学生先查看最新状态；
- 登录状态失效时返回登录页；
- 本地草稿不代表已经提交成功；
- 错误上报不得包含密码、验证码、完整身份资料或媒体内容；
- 学生不取得系统级原始审计事件、安全元数据或服务器运行日志 ZIP；系统内部留痕不能向学生暴露其他用户、管理员或教师的信息；
- “不允许隐藏备注”只约束打卡审核；打卡审核只产生正式结果、固定公开原因及可选公开补充说明，不另存内部审核备注。最终成绩管理不设置备注；
- 学生不能获得媒体内部存储信息；
- 当前不收集定位、轨迹或地图信息。

## 12. 明确不属于学生端的能力

- 手机号/短信登录、学生密码找回；
- 自由选班、多有效教学班、审批正常入班、自主退课或转班；
- 修改运动日期、正式计时、类别，覆盖或删除已提交材料和历史；
- 手工增加 60 分钟，伪造会话，按补证日期取得新日/周名额；
- 超过一次正常补证、自助延期申请、多级申诉、投票协商或自定义课程公式；
- 用事后照片冒充游泳前证据，使用截图直接换取时长；
- 查看最终分数、换算分、等级或排名，发起成绩调整审批；
- 将耐力跑用时计入打卡进度，或归档后新建补练；
- 采集定位轨迹、访问系统原始审计/运行日志、依赖通知已读决定结果；
- 使用模拟扫码、Fake Success 或合成工作区作为正式成功路径。

同日独立重新运动、一次补证和达标后继续记录已属于本版正式范围，不再沿用旧版对这些行为的全面禁止。

## 13. 学生端主流程

1. 通过有效邀请注册或登录并直接入班，验证学校邮箱。
2. 查看课程模板、两类目标、截止日和本人名单核对结果。
3. 在允许时间开始独立运动，需要时暂停，结束后保留准确会话事实。
4. 选择类别、填写说明并提交凭证；游泳遵守前后照片和限时受理规则。
5. 查看 AI 处理结果；正常自动有效，异常等待教师，技术故障不受罚。
6. 如被退回，在教师指定的 24/72 小时有效计时内提交一次补证；维护暂停、恢复后续计。正式受理后进入新的教师两工作日复核轮次，补证后判无效不再补证。
7. 查看系统自动计算的可计/实际计入分钟、分类进度和剩余目标。
8. 无效后可重新实际运动，日/周上限仍有效；达标后可继续记录运动。
9. 查看教师确认的原始体测数据，按需要提交免测或组织认证。
10. 接收期末提醒；如获准，在七天收尾期的指定窗口补练。
11. 查看本人结算数据和更正结果；分数由学校指定渠道反馈。
